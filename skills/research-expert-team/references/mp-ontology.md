## 1. Kimera（IJRR 2021）——如何把一个系统写成顶刊

### 1.1 选题解剖

- **缺口论证三要素法**：引言开篇不给"我们做了 X"，而是先立"高层场景理解的三要素"——(i) 度量-语义理解 (ii) 多层抽象 (iii) 静态+动态实体及其关系——然后逐一指出现有方法各缺哪一块。这个框架让审稿人**先接受你的评价标准，再看你填空**。
- **逐篇点名式缺口**（关键技法）：对最近邻工作不是笼统说"prior work has limitations"，而是精确到篇：Armeni et al. 2019 的 3DSG"假定标注网格已给定、不可行动（无 traversability）"；Kim et al. 2019"只抓物体、缺多层抽象"；两者"都不建模动态实体"。**每个 baseline 的死刑判决书都要具体到机制层面**。
- **动机锚点**：用人类认知差距开题（"current robots' internal representations still provide a partial and fragmented understanding"），再举一个普通读者秒懂的例子（机器人只懂"到达坐标 XYZ"，不懂"去厨房拿购物袋"）。顶刊引言 = 认知差距 + 具体反例 + 三要素框架。
- **期刊时机**：RSS 2020 已发 3D Dynamic Scene Graphs 短版，IJRR 版是把"表示+系统+数据集+应用"整合成完整叙事的**成熟期投稿**——期刊偏爱有会议预印本铺垫、但明确给出增量的工作。

### 1.2 论述解剖

**四贡献枚举（期刊论文的贡献结构模板）**：

1. **表示**：3D Dynamic Scene Graph（DSG）——分层有向图，节点=空间概念，边=时空关系；显式声明它是拓扑地图的**严格泛化**（"strict generalization of topological maps"——把新表示挂到旧标准上，让读者有已有坐标可攀）。
2. **引擎**：Kimera——"首个从视觉-惯性数据全自动构建 DSG 的空间感知引擎"，并把 SLAM 降格为其中一个模块（"generalizes SLAM, which becomes a module"——降维打击式的定位句）。
3. **评测+数据集**：真实+仿真数据集上的全面评测，**发布新数据集 uHumans2**（12 个拥挤室内外场景）。
4. **应用示范**：DSG 上的分层语义路径规划，展示"查询快几个数量级"。

**期刊专用章节**（会议论文没有的）：
- "Novelty with respect to previous work"独立小节——逐条列出相对自己 RSS/IROS 前作的增量（新回环机制 PGMO、实现并测试分层规划、更全面评测、新数据集、嵌入式硬件实时性）。**期刊审稿人必查自我重复，主动交代 = 免死金牌**。
- 超长 Related Work（第 7 节）+ 独立 Future Work 讨论。
- 设计理由前置：§2.6 "Why should we choose this set of nodes or edges rather than a different one?"——**主动回答审稿人一定会问的表示设计任意性质疑**，并用 Remark 1（规划查询）和 Remark 2（可组合性/可增删层）两个方框给出答案。

**写作技法**：
- Figure 1 一图讲完整个系统（DSG 分层结构 + 5 个能力缩略图）；
- 5 层 DSG 逐层形式化定义（节点属性、边语义、与上下层的连接规则），表示论文的"定义密度"是可信度的来源；
- 命名体系（Kimera-VIO/Mesher/Semantics/PGMO/Humans/Objects/BuildingParser）让系统论文可被逐模块引用。

### 1.3 论文骨架（IJRR 期刊结构模板，可直接对照模仿）

| 章节 | 功能 | 写作要点 |
|---|---|---|
| Abstract | 人类认知差距→DSG→Kimera→评测+数据集→应用 | 四贡献全在摘要里各占一句 |
| §1 Introduction | 三要素框架→逐篇点名缺口→四贡献枚举 | 先立法后填空；Novelty-vs-prior 独立段 |
| §2 3D Dynamic Scene Graphs | 逐层形式化定义（5 层）+ 设计理由（Remark 1/2） | 表示论文的定义密度=可信度 |
| §3 Kimera Engine | Core（VIO/Mesher/Semantics/PGMO）+ DSG（Humans/Objects/BuildingParser）逐模块 | 按线程/数据流组织，命名可被逐模块引用 |
| §4 Experimental Evaluation | 模块级+系统级+嵌入式实时+uHumans2 发布 | 逐模块独立证据链 |
| §5 Motivating Examples | 分层语义路径规划，查询加速比 | 应用收尾闭环 |
| §6 (Discussion) / §7 Related Work / §8 Conclusion | 超长文献综述+未来工作 | 期刊专用：Related Work 独立成节且厚 |

### 1.4 实验设计解剖

| 设计决策 | 具体做法 | 可迁移经验 |
|---|---|---|
| 模块级评测 | VIO 在 EuRoC 上与 SoTA 对比；mesh 实时性；物体/人体定位精度；房间划分正确性 | 系统论文必须**逐模块**给出独立证据，不能只报端到端 |
| 嵌入式实时性 | 在 NVIDIA TX2 上报告全管线实时运行 | 机器人论文的隐性门槛：桌面 GPU 数字不算数 |
| 自建数据集 | uHumans2：12 个场景、拥挤人群、室内外混合 | 评测缺口自建数据补——数据集本身成为引用资产 |
| 应用加速比 | DSG 分层规划 vs 体素规划，路径规划查询时间快几个数量级 | "新表示→下游可量化收益"闭环，证明 actionable 不是口号 |
| 真实数据定性 | 公寓+办公室实采 | 仿真定量 + 真实定性的标准组合 |

### 1.5 价值解剖（为什么 407 引且持续被引）

- **定义权**：DSG 成为 3D 场景图领域的标准词汇，后续论文（Hydra、ConceptGraphs、我们库里的 DynamicGSG/GraphWrit3R 全部）都要引它来定义坐标系。
- **开源+数据集+视频**三件套，引用门槛低。
- 期刊寿命长：IJRR 论文被教科书和综述反复引用，半衰期远超会议。

### 1.6 可迁移打法（写 OntoGS 类本体论文时照抄的清单）

1. 先立"三要素/三要求"评价框架，再填自己的空位；
2. 最近邻逐篇点名判死刑（机制层面，不是形容词层面）；
3. 新表示必须显式声明是哪个旧表示的泛化；
4. 系统论文：贡献=表示+引擎+评测(含新数据集)+应用四联装；
5. 主动设"设计理由"小节回答"为什么是这组节点/关系"；
6. 期刊投稿必带"相对前作增量"独立小节；
7. 逐模块评测 + 嵌入式实时性 + 下游任务的量化收益闭环。

## 2. ConceptGraphs（ICRA 2024）——基础模型时代如何写桥接论文

### 2.1 选题解剖

- **三要求框架**（与 Kimera 同构但更狠）：开篇立"表示应满足三要求"——可扩展高效、开放词汇、灵活细节层次——然后逐一击毙：逐点特征图"内存爆炸、不可扩展"；封闭词汇建图"限于训练类别"；现有 3D 场景图"封闭词汇"。**自己的方法被框定为三要求的同时满足者**。
- **时机判断**（教科书级）：2023 年 SAM/CLIP/GPT-4/LLaVA 刚成熟，"foundation models meet 3D"是当打之年的空位。相关工作分三组递进（封闭词汇建图→FM 3D 表示→3D 场景图），每组结尾留一个缺口句，最后一段"I-B Overview"把三个缺口合并成自己的定位。
- **卖点显式化**："off-the-shelf models，no training/finetuning, no 3D datasets"——零训练在 2023 年是巨大卖点（对比 3D 原生方法需要 Objaverse 级数据）。

### 2.2 论述解剖

**三贡献（应用导向桥接论文模板）**：
1. 物体中心建图系统（几何线索 × 2D 基础模型语义线索）；
2. 开放词汇 3D 场景图（高效结构化语义抽象）；
3. 真实轮式+足式机器人平台部署，展示感知+规划能力。

**叙事主线**：表示 → 构建管线（分割→关联→融合→字幕→关系→图）→ **六个下游任务**（分割、物体检索、导航、抓取、定位、地图更新）。把"一个表示的通用性"用任务广度证明——每个下游任务都是一次价值复利。

**写作技法**：
- 电话游戏/传话类比解释为什么闲聊式多智能体通信会失真（类比降低理解成本）；
- Figure 2 一图讲完管线（从 RGB-D 序列到 LLM 可规划的场景图文本）；
- 附录公开全部 prompt（GPT-4 字幕汇总 prompt、LLM 规划器 system prompt、JSON 节点格式）——**prompt 即方法的一部分，公开到可复现**；
- 贡献声明附录（Contribution Statement）逐一写明每位作者做了什么——大团队论文的信誉管理。

### 2.3 论文骨架（ICRA 会议结构模板）

| 章节 | 功能 | 写作要点 |
|---|---|---|
| Abstract | 三要求→方法一句话→六下游任务 | 零训练卖点进摘要 |
| §I Introduction + I-A Related Work | 三要求框架；相关工作三组递进各留缺口句 | 会议把 related work 嵌入引言尾部 |
| §I-B Overview of Our Contribution | 三贡献概览 | 独立小节，审稿人直接翻这里 |
| §II Method | II-A 物体建图（分割→关联→融合→字幕）/ II-B 场景图生成 / II-C LLM 规划 / II-D 实现细节 | 符号化模块接口 Seg(·)/Embed(·)/LVLM(·)/LLM(·) |
| §III Experiments | A 图构建精度 / B 分割 / C 检索 / D 复杂查询 / E 物体搜索+可穿越性 / F 开放词汇抓放 / G 定位与地图更新 / H 限制 | 实验子节=能力矩阵，每子节一个能力声明 |
| §IV Concurrent Work / §V Conclusion | 并发工作处理 | 并发竟争者的礼貌化区分 |
| Appendix | 贡献声明+全部 prompt+查询样例 | prompt 即方法，公开到可复现 |

### 2.4 实验设计解剖

| 设计决策 | 具体做法 | 可迁移经验 |
|---|---|---|
| 评测协议沿用 | 开放词汇分割沿用 ConceptFusion 协议（可直接对比） | 找到前任的评测协议并沿用，避免"自造指标"质疑 |
| **自建更强 baseline** | 不满足于比 ConceptFusion 强，自己构造 ConceptFusion+SAM（换更强分割器）再比 | 主动加固 baseline 是审稿人最买账的动作之一 |
| 人工评测 | AMT 三人投票：节点精度 ~70%、边精度 ~90%、重复检测 0-5 个 | 无 ground truth 的新任务→人工评测协议要设计得可量化 |
| **查询类型学** | 检索任务分 descriptive/affordance/negation 三类，分别报告 R@1/2/3 | 任务分类法本身就是贡献——后来者会沿用你的分类 |
| 真机演示矩阵 | Jackal（物体搜索含"常见位置推理"+可穿越性推理）、Spot（开放词汇抓放）、AI2Thor（定位+地图更新） | 每个演示对应一个"传统方法做不到"的能力声明 |
| 诚实限制节 | LVLM 字幕错误、小/薄物体漏检、LLM 推理成本 | 限制写得越具体，论文越可信 |

### 2.5 价值解剖（671 引的构成）

- **配方可复制性**：模块化设计（Seg(·)/Embed(·)/LVLM(·)/LLM(·) 全部可替换），社区可以无限魔改——每个魔改都引你；
- **接口标准化**："场景图→JSON 文本→LLM 规划"的接口模式成为后续无数工作的默认模式；
- 桥接论文的天花板来自两侧生态（FM 生态 × 机器人生态）的乘积。

### 2.6 可迁移打法

1. 时机>天赋：押注"两个成熟生态的交点"（当下类比：3DGS × LLM 推理、Ontology × 生成式评测）；
2. 三要求框架 + 逐组相关工作留缺口句；
3. "零训练/零数据"类反差卖点显式写进摘要；
4. 下游任务矩阵证明通用性（≥4 个任务，每个配真机或仿真演示）；
5. 自建更强 baseline 再击败它；
6. 为新任务设计可沿用的人工评测协议 + 查询/任务分类法；
7. prompt 全部进附录；
8. 限制节写到审稿人无话可说。

## 3. 方向综述：本体/场景图方向投稿打法清单

**选题**：用"表示三要求"框架找交点缺口；对标 Kimera（系统级）或 ConceptGraphs（配方级）两条路线之一，不要走中间。2026-10 方向演进（检索印证）：开放词汇 3D 场景图已从会议配方成熟至 TPAMI 期刊层（Hyperbolic 层级 3D 表示，TPAMI 2026），活跃轴为**层级化/动态环境（LOST-3DSG）/单目前馈（LEXI-SG）/功能场景图（Open-Vocabulary Functional 3D Scene Graphs）**——OntoGS 类投稿的差异化应避开已成熟轴，押这些新轴或其组合。
**论述**：新本体/场景图表示必须 (a) 声明是哪张旧图的泛化 (b) 给出设计理由小节 (c) 定义节点/边/层的形式化。OntoGS 类论文的加分项：把"本体词汇表"的可组合性与 DSG 的 Remark 2 对齐。
**实验**：Replica/AI2Thor/HM3D + 真机（哪怕一个）；模块级指标 + 下游任务收益闭环；人工评测协议 + 查询分类法；AMT 三人投票式设计。
**基线**：库内必比 DynamicGSG、GraphWrit3R、Graph-GSReg、Prior-SG（场景图侧）+ SATURN/KLDrive（神经符号侧）——见 SKILL.md §2.1 选型表；主动加固最强 baseline。
**价值**：冲"定义权"（新表示成为后续工作的引用坐标系）或"配方权"（可复制模块化管线）；开源+数据集+prompt 三件套是引用引擎。
**红线**：表示设计任意性质疑必须 preempt；期刊投稿必带与前作增量小节；每个能力声明配一个演示。
