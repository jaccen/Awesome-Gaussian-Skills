
# 专利权利要求书撰写指南

## 一、权利要求书的法律定位

权利要求书是确定专利保护范围的法律文件，其作用是：
- 划定保护边界（审权阶段与侵权判定均以权利要求为准）
- 说明书用于解释权利要求，但不能扩大其范围

## 二、撰写基本原则

### 2.1 技术特征充分原则

每一项权利要求必须包含**解决技术问题的全部必要技术特征**，否则因"缺少必要技术特征"被驳回。

反面案例：仅写"一种图像处理方法，包括对图像进行增强处理"→过于笼统，缺少具体手段。

### 2.2 语言确定性原则

- 不得使用"大约""左右""优选""例如""最好是"等不确定用语
- 不得使用"厚""薄""强""弱"等无确定标准的相对词（除非有明确定义）
- 不得纯功能性限定（如"一种装置，能够实现XXX功能"而无具体结构）

### 2.3 一致性原则

- 同一技术特征在整个权利要求书中只能用一个术语
- 首次出现的术语在其前不加"所述"，之后引用时加"所述"
- 前序部分与特征部分的划分应与现有技术边界对齐

## 三、独立权利要求

### 3.1 结构

```
一种[技术主题]的方法/系统/装置，其特征在于，包括：
[前序部分：现有技术共有的技术特征]；
其特征在于，
[特征部分：区别于现有技术的技术特征]。
```

### 3.2 撰写要点

1. **适度宽泛**：独立权利要求应争取较宽保护范围，但须有技术特征支撑（不能是纯概念）
2. **层次递进**：必要特征放在独立权利要求；可选/优选特征放在从属权利要求
3. **方法+系统成对**：独立权利要求至少写方法类和系统类各一项，覆盖不同侵权场景

### 3.3 方法类独立权利要求模板

```
1. 一种[技术主题]方法，包括：
   [前序特征A]；
   [前序特征B]；
   其特征在于，所述方法还包括：
   [特征C]：[具体步骤描述]；
   [特征D]：[基于特征C的结果执行的具体操作]；
   [特征E]：[输出/确定结果]。
```

### 3.4 系统/装置类独立权利要求模板

```
N. 一种[技术主题]系统，包括：
   [模块A]，用于[功能描述，对应方法步骤]；
   [模块B]，用于[功能描述]；
   其特征在于，所述系统还包括：
   [模块C]，用于[对应特征C]；
   [模块D]，用于[对应特征D]；
   [模块E]，用于[对应特征E]。
```

## 四、从属权利要求

### 4.1 结构

```
M. 根据权利要求K所述的[技术主题]方法/系统，其特征在于，
   [进一步限定的技术特征]。
```

### 4.2 撰写策略

1. **递进式限定**：每项从属权利要求在所引用的权利要求基础上增加一个技术维度
2. **多层展开**：
   - 第一层（引用独立权利要求）：限定核心步骤的具体实现方式
   - 第二层（引用第一层从属）：限定实现方式的参数/条件
   - 第三层：限定优选参数范围或特殊场景适应
3. **避免引用冲突**：引用多项权利要求时（"根据权利要求1-3任一项"），限定的特征必须在所有被引用项基础上都有意义
4. **数量建议**：3-8项从属权利要求，保证关键创新点均有展开

## 五、常见缺陷与防范

| 缺陷类型 | 表现 | 防范 |
|----------|------|------|
| 缺少必要技术特征 | 独立权利要求未包含完整技术方案 | 检查：去掉该特征后方案是否仍可实施 |
| 保护范围过窄 | 独立权利要求包含过多实现细节 | 非必要细节移至从属权利要求 |
| 引用不当 | 从属权利要求引用的权利要求中无对应基础 | 检查所引用的权利要求是否包含可进一步限定的特征 |
| 术语不统一 | 同一概念在不同权利要求中用不同术语 | 全文术语表校验 |
| 功能性限定 | 仅描述功能而无具体技术手段 | 每个功能限定必须关联具体结构或步骤 |

## 六、软件/算法类专利特殊注意事项

1. **避免纯算法权利要求**：必须与具体技术领域结合（如"一种图像处理方法"而非"一种数据处理方法"）
2. **步骤级展开**：算法的每个关键步骤应作为独立技术特征
3. **数学公式**：在权利要求中用文字描述公式含义，避免纯数学符号（公式可在说明书中详细给出）
4. **计算机可读介质**：可增加一项"一种计算机可读存储介质"类权利要求
