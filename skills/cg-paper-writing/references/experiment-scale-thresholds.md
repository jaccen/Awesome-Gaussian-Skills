# 实验规模门槛表（Experiment Scale Thresholds）

> **用途**：判断"实验够不够"，在投稿前自查、在 rebuttal 中防守"实验不足"这类攻击。
> **适用**：3DGS / 具身智能 / 空间智能 / Agent 四方向（含 3DGS+具身等交叉方向）。
> **整理日期**：2026-10-21
>
> ⚠️ **性质声明（务必先读）**：下表是**社区惯例的经验区间**，**不是任何会议/期刊的官方要求**。它来自对 `domain-exemplar-templates.md` 所列范文实验规模的观察 + CoRL/ML 顶会写作指南的通识。不同子方向、不同贡献类型（方法/系统/基准）差异很大。**投稿前必须用目标 venue 近两年 3-5 篇 accepted papers 校准**——同一会议不同年份的期望也可能变化。表内数字用于"自检是否明显偏少"，不是"达到即通过"。

---

## 1. 四方向门槛速查

### 1.1 3DGS（渲染 / SLAM / 压缩 / 前馈 / 生成）

| 维度 | 经验下限 | 常见做法 | 备注 |
|------|---------|---------|------|
| 主对比数据集 | 3 个 | 5-7 个 | 常用 Mip-NeRF 360 / Tanks & Temples / Deep Blending / LLFF；大场景加 MatrixCity / UrbanScene |
| 基线数量 | 5 个 | 8-12 个 | 必须含：①3DGS 原版 ②最近 6 个月 SOTA ③同赛道 1-2 个改进版 |
| 消融 | 每个提出模块 1 行 | 模块消融 + 关键超参 3 档敏感性 | 缺任一模块的消融会被直接质疑"该模块无用" |
| 效率指标 | FPS + 训练时间 + 显存 | 三者齐 + GPU 型号 + 分辨率 + 高斯数 | "real-time" 必须给 Hz，否则视为空话 |
| 随机种子 | 3 seeds（报 mean±std） | 5 seeds | 3DGS 单次训练较确定，但随机初始化需多 seed |
| 定性对比 | teaser + 2 组局部放大 | 4-6 组 + 失效案例 | 局部放大框是 3DGS 论文的行业惯例 |
| 代码/权重 | 强烈建议 | 多数 CVPR 论文开源 | 不开源会削弱 reproducibility 评分 |

> **压缩/加速子方向加一条**：模型体积（MB）+ 解码耗时必须与 FPS 同表呈现，只报质量不报体积会被判"没解决压缩问题"。

### 1.2 具身智能（VLA / 机器人操作 / Sim2Real）

| 维度 | 经验下限 | 常见做法 | 备注 |
|------|---------|---------|------|
| 任务数 | 4 个任务族 | 6-10 个 | CoRL 论文常见 4-8；单一任务需极强新意 |
| 随机种子 | 3 seeds | 5 seeds | 机器人策略方差大，3 seeds 是底线 |
| 每任务每 seed episode | 20 次 | 50 次 | 成功率的分母必须写清 |
| 平台 | sim 或 real 至少 1 个 | sim + real 双验证 | 纯 sim 必须讨论 sim2real 差距 |
| 基线 | 3 个 | 4-6 个 | 必须含 1 个强 VLA 基线（OpenVLA / π₀ / Octo / DP3 / ACT 类） |
| 消融 | 3 个组件 | 每组件 + 数据规模曲线 | 数据缩放曲线在 VLA 论文中权重很高 |
| 视频材料 | 必备 | 每任务 1 段 + 失败案例 | 具身论文没有视频，审稿人无法判断真实性 |
| 统计报告 | mean ± std（跨 seed） | + 置信区间 | 只报最好一次 run 属硬伤 |

> **CoRL 特别约定**：setup 节的协议细节（谁操作、几次重置、成功判据）必须写进正文，不能全推附录；表格 caption 必须自带 `k seeds × n episodes`。

### 1.3 空间智能（世界模型 / 3D-LLM / 场景图 / 空间推理）

| 维度 | 经验下限 | 常见做法 | 备注 |
|------|---------|---------|------|
| 主 benchmark | 3 个 | 4-6 个 | 世界模型类常用 DMC / Noisy-TV / 控制任务；3D-LLM 类用 ScanQA / SQA3D / ScanRefer |
| 通用强基线 | 必须含 | GPT-4o / Gemini / Claude 至少 1 个 | 空间推理不比通用大模型，会被质疑"意义何在" |
| 新任务/新基准 | 可选但高价值 | 新任务 + 新数据集 + 统计描述 | 新数据集必须给规模、标注类型、采集方式、多样性分析 |
| 消融 | 每模块 1 行 | 模块 + **训练阶段**（预训练/对齐/指令微调） | LMM 类必须拆阶段，否则说不清收益来自哪一步 |
| 误差指标 | 不能只报 accuracy | + 距离/朝向误差（如 mARE） | 空间任务只报准确率会被质疑"精度未测" |
| 泛化 | unseen scene 或 zero-shot 之一 | 两者都有 | 空间智能的核心卖点是泛化 |
| 定性 | 空间关系可视化 | 3-5 组 + 失败案例 | 3D 框/距离标注图最直观 |

> **世界模型类特别一条**：必须报**规划/控制的下游效果**，只报预测 loss 或重建质量会被判"没证明有用"。

### 1.4 LLM Agent（推理规划 / 工具调用 / 多智能体）

| 维度 | 经验下限 | 常见做法 | 备注 |
|------|---------|---------|------|
| 任务族 | 3 个 | 4-6 个 | 通常跨类型：知识问答 / 代码 / 网页 / 具身 |
| 公认 benchmark | 3 个 | 4-6 个 | 如 HotpotQA / ALFWorld / WebShop / HumanEval / AgentBench |
| 基线 | 4 个 | 6-8 个 | 必须含：①纯 prompting 基线 ②训练类方法 ③最新 SOTA |
| 消融 | 每组件 1 行 | reasoning / action / memory 分别拆 | 组件拆不干净会被质疑"增益来自 prompt 长度" |
| **成本指标** | 必备 | token 消耗 + 调用次数 + 延迟 | Agent 论文不报成本＝隐藏代价，近年已成硬要求 |
| 随机种子 | 3 seeds | 5 seeds | LLM 采样有随机性，单次结果不可信 |
| 人工评估 | 涉及可用性时必备 | + 标注者协议、一致性指标 | 涉及"可解释/可信"主张时必须有人评 |
| 失败分析 | 强烈建议 | 分类统计失败原因 | Agent 论文的失败分析往往比成功案例更有说服力 |

## 2. 交叉方向如何叠加

| 交叉类型 | 门槛取法 | 额外要求 |
|---------|---------|---------|
| 3DGS + 具身 | 任务/episode 按具身，质量/效率按 3DGS | 需同时报**任务成功率**与**重建质量**，两者不可互相替代 |
| 3DGS + 空间智能 | benchmark 按空间智能，效率按 3DGS | 需证明 3DGS 表示对空间推理**有增量**（消融掉 3DGS 换成点云/网格） |
| Agent + 具身 | 任务按具身，成本按 Agent | 需报**真机**结果；纯仿真 Agent 论文说服力弱 |
| 3DGS + Agent | 任务按 Agent，感知按 3DGS | 必须做"感知模块替换"消融（3DGS vs NeRF vs 点云） |

> **通用原则**：交叉方向的实验量 ≈ 两个方向门槛的**并集**，不是交集。审稿人会同时用两个社区的标准要求你。

## 3. 「实验够不够」八问自检

投稿前逐条回答，任一为"否"就要补：

1. 每个 claim 都能指到**具体某张表/某张图**吗？
2. 最强基线是**近 6 个月**的 SOTA 吗？
3. 所有对比方法是否**同数据集、同 split、同评测协议**？（跨口径拼表＝硬伤）
4. 消融是否覆盖**每一个**你声称有贡献的模块？
5. 效率/成本指标是否标了**硬件与设置**？
6. 随机性结果是否报了 **mean ± std + seeds 数**？
7. 失败案例有没有**至少一组**？（全胜叙事反而可疑）
8. 有没有一个实验是**只有你能做、别人做不了**的（护城河）？

## 4. 被质疑"实验不足"时的三种应对

| 审稿意见形态 | 首选应对 | 次选 | 不可做 |
|-------------|---------|------|--------|
| "缺少与 X 的对比" | **补跑 X**（rebuttal 期内最有效） | 论证 X 设置不可比并给替代基线 | 只用文字辩解"X 不重要" |
| "消融不充分" | 补关键模块消融 | 用已有实验反推 + 承认局限 | 把相关性说成因果 |
| "只在仿真验证" | 补小规模真机 | 明确 claim 限定在仿真 + 讨论差距 | 模糊表述成"已泛化到真实世界" |

> **降 claim 也是合法解法**：若确实无法补实验，把主张从"通用"收窄到"在该设定下"，并在 Limitations 明说。审稿人反感的是"证据不足却坚持大 claim"，不是"证据有限但表述克制"。

---

## 5. 校准方法（每次投稿前必做）

1. 在目标 venue 近两年 proceedings 里找 **3-5 篇同子方向 accepted papers**；
2. 数它们的：数据集数 / 基线数 / 消融行数 / seeds / episodes / 是否开源；
3. 取**中位数**作为你的目标值（不是最小值）；
4. 若你的实验量低于中位数，准备好两条理由：①任务更难 ②计算受限但给出了替代证据；
5. 把校准结果写进实验计划（可由 `3dgs-experiment-planner` 技能承接）。

> **不要对标 best paper**：best paper 的实验规模常是常态的 1.5-2 倍，对标它会导致过度投入。
