## New Methods (6)

### Feed-Forward / Generalizable (2)
- **GADA** [arXiv:2607.00595] (ICML 2026) — Geometry-Aware Deformable Aggregation for image-based 3DGS; deformable offsets with implicit confidence weighting; 2.13× faster FPS with improved PSNR
- **InvSplat** [arXiv:2607.02301] — Inverse feed-forward scene splatting; predicts structured 3D Gaussians with intrinsic material attributes (albedo, metallic, roughness) for relighting without post-hoc decomposition

### Material / Relighting (1)
- **MGM (Large Material Gaussian Model)** [arXiv:2509.22112] — Relightable 3D generation with full PBR materials; multiview material diffusion + Gaussian material representation

### Robustness / Physics-Guided (1)
- **DualPhys-GS** [arXiv:2508.09610] — Dual physically-guided 3DGS for underwater scene reconstruction; joint attenuation-scattering physics + lighting decomposition

### Provenance / Security (1)
- **GaussTrace** [arXiv:2606.10612] (ICML 2026) — 3DGS provenance analysis via evidence-driven LLM reasoning; directed provenance graphs for 3DGS model IP protection and forensics

### 3DGS Hardware Acceleration (1)
- **StereoGS** (2026) — Energy-efficient stereoscopic 3DGS rendering processor; dual-eye shared compute and memory bandwidth for VR/AR

## Notable Trends

- **Geometry-aware deformable aggregation**: GADA (ICML 2026) introduces learnable deformable offsets with implicit confidence weighting for image-based 3DGS — moves beyond static pixel-aligned prediction toward geometry-adaptive feature aggregation, achieving 2.13× FPS improvement
- **Intrinsic PBR in feed-forward pipelines**: InvSplat and MGM bridge the gap between feed-forward 3DGS and PBR relighting — predicting albedo/metallic/rougness directly in a single forward pass eliminates the need for post-hoc intrinsic decomposition, enabling real-time relightable asset generation
- **3DGS provenance & IP protection**: GaussTrace (ICML 2026) opens a new research direction — using LLM-driven evidence reasoning to trace 3DGS model provenance from Gaussian scene attributes, enabling forensic analysis of AI-generated 3D content
- **Physics-guided domain adaptation**: DualPhys-GS demonstrates that physically-grounded models (attenuation-scattering) can generalize 3DGS to extreme environments (underwater) without large-scale domain-specific training data
- **Stereoscopic hardware acceleration**: StereoGS extends 3DGS hardware acceleration from monocular to stereoscopic rendering — critical for VR/AR deployment where dual-eye consistency and shared compute are essential

# v0.4.4 — 2026-07-23 (Skill Addition)

## Summary

New 15th skill: 3dgs-training-debugger — the first skill covering the **runtime training phase** of 3DGS. Fills the #1 gap identified in the skill ecosystem: all 14 existing skills operated BEFORE training (code review, experiment planning) or AFTER training (visualization, paper writing). This new skill covers DURING training: OOM crashes, NaN losses, divergence, densification failures, visual artifacts, checkpoint issues, and novel method stability.

## New Skill (1)

### 3dgs-training-debugger (v1.0.0)
- **Scope**: Runtime training failure diagnosis for vanilla 3DGS and 50+ novel methods
- **10 sections**: Training Monitoring Checklist, Failure Diagnosis Decision Tree, OOM & Memory Management, Artifact Diagnosis Catalog, Hyperparameter Tuning Guide, Convergence Analysis, Distributed & Multi-GPU Training, Checkpoint & Resume, Novel Method Training Stability, Training Runtime Bug Patterns
- **60+ runtime bug patterns** across 8 categories: Initialization (6), Densification (8), Optimization (7), Memory (6), Convergence (7), Artifacts (8), Multi-GPU (6), Novel Method (12+)
- **3 reference files**:
  - eferences/runtime-bug-patterns.md — Full 60-pattern database with symptoms, root causes, diagnostics, fixes
  - eferences/convergence-trajectories.md — Expected PSNR/SSIM/Gaussian count at key iterations for 6 method families
  - eferences/vram-gpu-table.md — Precomputed VRAM requirements, GPU recommendations, quick estimator formula
- **Self-Check Loop**: SC-1 (Symptom Verification) → SC-2 (Diagnostic Completeness) → SC-3 (Fix Verification)
- **Red Lines**: 5 categorical prohibitions (no invented data, no hallucinated citations, no silent speculation, no method misattribution, no one-size-fits-all fixes)
- **Relationships**: Complements 3dgs-code-reviewer (static analysis → runtime debugging), 3dgs-experiment-planner (design → execute), 3dgs-engineering-guide (train → deploy)
