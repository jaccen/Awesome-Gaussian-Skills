
# 软件著作权登记材料指南

## 一、登记概述

软件著作权（软著）登记通过**中国版权保护中心（CPCC）**在线提交，所需核心材料：
1. 软件著作权登记申请表（在线填写）
2. 软件说明书（10-15页）
3. 源代码文档（前后各30页，共60页；不足60页的提交全部）

本技能生成第2、3项材料。

## 二、软件说明书

| 页脚 | 页码 |
| 截图 | 至少6张界面截图或功能演示图 |
| 语言 | 中文，面向审查员，非开发者 |
| 时态 | 以"本软件""可以"等客观描述为主 |

### 2.3 撰写注意事项

1. **语言面向审查员**：避免"我们""我"等人称，用"本软件""用户"
2. **截图占位**：用 `[截图: 功能名称界面]` 标注，用户后续替换实际截图
3. **功能完整性**：说明书须覆盖软件全部主要功能，不能只写核心模块
4. **版本一致性**：软件名称和版本号在说明书头部、页眉、源代码文档中必须完全一致
5. **禁止广告性语言**：不得使用"业界领先""革命性""首创"等宣传用语
6. **技术深度适中**：写明"做什么"和"怎么用"，不需要写底层算法实现细节

## 三、源代码文档

### 3.1 格式规范

| 项目 | 要求 |
|------|------|
| 页数 | 前30页 + 后30页 = 60页；总代码不足60页则全部提交 |
| 每页行数 | ≥50行 |
| 页眉 | 软件名称+版本号 |
| 页脚 | 页码（从第1页连续编号） |
| 格式 | 等宽字体、语法高亮可不加 |
| 内容 | 去除空行；注释可保留 |

### 3.2 代码选取策略

**总行数 ≤ 3000行**：全部代码按模块顺序排列。

**总行数 > 3000行**：
1. **前30页（约1500行）**：按模块逻辑顺序，从程序入口开始选取
   - main函数 / 入口文件
   - 核心模块初始化
   - 关键功能模块的起始部分
2. **后30页（约1500行）**：选取代码尾部
   - 核心功能收尾部分
   - 配置/常量定义
   - 辅助工具函数
   - 入口文件的收尾（如有）

**避免选取**：
- 第三方库代码（node_modules、vendor目录等）
- 自动生成代码（pb生成文件、swagger生成文件等）
- 纯配置文件（package.json、.yaml等无逻辑的配置）
- 测试用例（非核心逻辑）

### 3.3 代码格式化要求

```
┌─────────────────────────────────────┐
│ XX软件 V1.0                          │  ← 页眉
├─────────────────────────────────────┤
│  1 | #include <iostream>            │
│  2 | #include "core/processor.h"    │
│  3 |                                │
│  4 | namespace MyApp {              │
│  5 |                               │
│ ...                                 │
│ 50 | }  // namespace MyApp          │  ← 每页≥50行
├─────────────────────────────────────┤
│                                     │ 1  │  ← 页脚页码
└─────────────────────────────────────┘
```

### 3.4 敏感信息清除

源代码文档在生成时必须清除以下内容：

| 清除项 | 处理方式 |
|--------|----------|
| API密钥/Token | 替换为 `***REMOVED***` 或删除该行 |
| 数据库密码 | 替换为占位值 |
| 内部URL/IP | 替换为 `192.168.x.x` 或 `example.com` |
| 个人信息 | 删除或脱敏 |
| 内部项目代号 | 替换为软件正式名称 |

## 四、常见驳回原因

| 驳回原因 | 说明 | 防范 |
|----------|------|------|
| 说明书不完整 | 功能描述不全面，截图不足 | 确保功能全覆盖，截图≥6张 |
| 源代码行数不足 | 每页不足50行 | 格式化时严格控制每页行数 |
| 软件名称不一致 | 申请表/说明书/源代码中软件名不同 | 全流程统一名称校验 |
| 版本号缺失/不一致 | 各材料版本号不统一 | 使用同一版本号常量 |
| 代码含第三方代码 | 提交的代码中包含非自主开发部分 | 排除node_modules等第三方目录 |
| 源代码与说明书不对应 | 说明书描述的功能在代码中找不到 | 代码选取应覆盖说明书所述功能模块 |

## 五、软著与专利的协同策略

同一软件项目建议**先软著后专利**：

1. 软著登记门槛低、周期短（1-2个月），可快速获得版权保护
2. 专利申请审查周期长（1-3年），但保护力度更强
3. 软著说明书中的技术描述可作为专利说明书的素材基础
4. **关键区别**：软著说明书侧重"功能与使用"，专利说明书侧重"技术方案与创新"
5. 软著保护表达（代码），专利保护方案（技术特征），两者互补

申请软著时注意：提交的源代码和说明书内容会在登记后公开，**不要在软著材料中包含希望日后申请专利的核心创新细节**。
