# 文献覆盖、全文证据与目标期刊适配

适用于扩展检索、补齐论文全文、开题与投稿质量优化。2026-11-18 核对工具文档；文档能力不等于本机已安装或运行成功。

## 从现有项目接续

定位项目 README、主张—实验—图表记录、配置与结果索引。分别登记项目、阶段、下一项可验证动作、依赖。目录库是检索起点；安装版技能没有 data/ 时，定位实际知识库根目录并记录快照日期，不能把技能目录假定为仓库根目录。

## 文献发现与获取分开执行

1. 将研究问题拆为任务、对象/表示、机制、评测、失败条件；扩展中英文同义词。加入不含 3DGS/Agent 字样的机制近邻，避免关键词自我封闭。
2. 先查本地索引，再按可用性组合 arXiv、OpenAlex/Semantic Scholar 引用网络、Crossref 元数据，以及 CVF/ACL/会议或期刊官网。GitHub 用于定位代码，不能独立证明论文结论。中文来源与跨学科来源按问题补充；没有接口或权限就记录缺口。
3. 从最接近工作做前向、后向引用追踪；区别检索引擎结果与原始出版来源。记录查询、时间范围、来源、分页上限、错误和停止条件。预算耗尽或接口失败标 incomplete，不能声称完整覆盖。
4. DOI 规范化、arXiv 基础 ID 归并版本，并记录预印本与正式版的关系。标题/作者/年份近似匹配只产生待核对项；正式版不同结果不能被旧版覆盖。
5. 按任务、设定、机制和评价协议筛选；保留排除理由。分别输出直接竞争工作、机制近邻、可复现基线和背景材料。引用量与新旧不能单独决定相关性。
6. 优先从出版社 OA、会议页、arXiv、机构库获取可访问全文。已有 DOI/arXiv 清单可交给批量下载器；下载器不能替代主题发现。付费文献可记录机构访问或作者稿缺口。保留现有授权边界，不因工具支持而自动开启额外来源。
7. 核验内容确为 PDF/HTML/JATS，核对标题、作者和标识符，保存版本、来源 URL、内容校验和与获取时间；不能仅凭 .pdf 后缀或 HTTP 200 判成功。表格、公式和关键数字需要页面视觉复核。解析失败单独登记。
8. 文献状态分别为 metadata_only、abstract_only、fulltext_fetched、parsed、claim_checked。仅有摘要不能确认消融、理论证明或实验设置；无全文不能推断方法没有某项能力。

## 三个外部工具的职责

- [scholar-mcp](https://github.com/gustavokch/scholar-mcp)：候选发现、引用数据与全文解析的可选统一接口。先检查实际暴露的工具、认证和服务可用性；不能把 README 的端到端能力视为已连接。PubMed/PMC 优势偏生物医学，CV/Agent 需保留会议官网和 arXiv。
- [scihub-cli](https://github.com/Oxidane-bot/scihub-cli)：已知 DOI/arXiv/URL 的批量全文获取、候选来源回退和 PDF 校验。适合补齐全文层，不等于扩大主题召回。
- [research-fetch-skill](https://github.com/Adamkadaban/research-fetch-skill)：网页、论文和视频资料获取的轻量辅助技能。网页/视频陈述应回到原始论文核验；本机 Windows 需检查 Bash 等实际依赖。

不要同时叠加三个默认重试链。一个任务选择一个主调度器，统一去重、缓存、超时、速率限制和失败记录；不自动修改 MCP 配置，不把未安装工具写成可用工具。API 密钥和邮箱从用户现有配置读取，日志不输出秘密。Unpaywall 需要真实邮箱，缺少时跳过并报告。

## 可复查的记录

沿用项目现有表；缺少时采用以下字段，不必创建空文件：

- 检索记录：query_id、查询、来源、日期/范围、分页/预算、状态、错误。
- 文献记录：paper_id、DOI、arXiv/version、标题、发现来源、相关性与理由、排除理由、全文来源、获取/解析状态、本地路径、checksum。
- 主张证据表：主张 ID、正文表述/类型、来源版本与页/节/表、实验配置、结果或图表位置、核验状态、下一步。区分计划、已有待核验结果和已完成核验结果。

## 如何验证是否真的提高数量

冻结同一主题、时间范围、检索预算和相关性标准，保存旧流程与新流程各自结果；引擎顺序变化和时间差需披露。可先用现有重点选题试跑，不预设必须收集几百篇。

- 发现增量：新流程中经筛选相关且不在旧流程的唯一论文数。未知全部相关文献时不能声称真实召回率。
- 参考集覆盖：由独立建立的相关论文参考集计算命中比例，明确它只是参考集覆盖；参考集不能完全由被测系统自己生成。
- 相关精度：筛选相关唯一论文数 / 实际筛选唯一论文数，抽样审查需注明抽样方法。
- 全文成功率：对同一冻结目标清单，身份核验通过的全文数 / 目标论文数。另报可用全文新增数、关键主张可定位证据比例、耗时/调用成本和各类失败。
- 分别报告 3DGS 与 Agent、近期与早期文献；同篇多版本不重复计数。仅增加下载文件、摘要或重复条目不算相关论文增量。

## 写作与期刊适配

开始定稿前明确目标期刊、文章类型和论文主张。目标未定时只给条件性匹配与需要补齐的证据，不编造录用概率。

1. 核对当年官网 scope、文章类型、模板/篇幅、匿名、数据代码、AI 使用披露和补充材料要求，记录 URL 与日期。无法核验的项目保持 unresolved。
2. 选取目标期刊近期与题材/贡献类型接近的论文做对照，比较问题定位、证据种类、基线协议、局限和复现信息；公开录用论文只能说明存在这种写法，不能证明采用它会提高录用率。
3. 每项贡献对应最接近工作、明确差异、判别实验、失败条件和原始证据。优先修补会改变结论的缺口，再润色语句。不能仅因没有搜到而声称首次。
4. 按主张选择数据集和基线，包含直接竞争与强简单基线；匹配数据划分、模型、工具权限、预算和硬件。场景、任务、种子、视图分清独立单位；重复数与统计方法由变异、精度、配对结构及分布决定，不机械规定 3 seeds 或必做 t 检验。
5. 摘要只写已核验数字及其条件；未测量数字不能为了模板补入。引言讲清具体问题、近邻不足和可检验贡献；相关工作包含反证与竞争解释。证据不足就缩小结论。
6. 预审提供具体位置、问题、影响、证据、修改动作和完成标准。角色视角不等于真实独立专家；没有实际启动子代理就不能称已召开专家团。
7. 本地交付稿件、引用核验记录、主张—实验—图表表、复现说明和投稿要求对照表。未完成实验显式登记；不以检查表填满冒充可投稿。

改进目标是减少漏检、错误新颖性判断、不可比实验、缺证据结论与期刊 scope 不匹配。实验质量和表达可以改进；录用决定仍依赖实际工作与评审。

## 已接入项目执行入口

三个工具的固定版本适配器已加入仓库：从项目根目录执行 `python scripts/research_tools.py doctor` 检查，`setup` 安装。详见 [科研工具集成](../../../integrations/research-tools/README.md)。执行脚本以仓库根目录为基准；安装状态与当前网络能力以 doctor 和实际验证为准。
