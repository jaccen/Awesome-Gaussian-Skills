**结论**：编号层面确实零虚构——所有 arXiv ID 都能查到真实论文。
**风险点**：名称与论文的对应关系存在系统性错配，典型案例如下。

| 库内条目 | 库内 arXiv ID | 该 ID 的真实论文 |
|----------|---------------|------------------|
| Scaffold-GS | 2312.13209 | *Toda brackets in n-angulated categories*（纯数学） |
| NegGS | 2405.14786 | *The TESS-Keck Survey XX: 15 New TESS Planets*（天文） |
| CityGaussian | 2401.02379 | *Detection and Discovery of Misinformation Sources* |
| GaussRender | 2503.07476 | *SOGS: Second-Order Anchor for Advanced 3D Gaussian Splatting* |
| GaussianDreamer | 2312.05941 | *ASH: Animatable Gaussian Splats* |
| SuGaR | 2312.13253 | *Conditional Image Generation with Pretrained Generative Models* |

其中 `DGD-v2`（库内 2412.03844，真实论文 *HybridGS*）同时命中两类问题：
**名称带 `-v2` 伪续作后缀**且**链接指向无关论文**——与既有的反幻觉约定中
「警惕在真实方法名后派生 -v2 / -2 / -AD 后缀的伪续作」完全吻合，该类模式应在后续扫描中专项排查。

## 四、待处置项与建议方案

### 建议 1：66 条 A 类——先核验、后改 ID

流程：`ti:"<名称>"` 检索 → 确认候选论文的方法名/任务领域与库内 `desc` 一致 → 改写 `arxiv_id`，
并同步 `venue` / `year`。**不建议直接套用候选列**：`3DGS`、`SuGaR`、`EMGS`、`LRG`、`RAF`、
`GS-LLM`、`GS-Physics`、`Deformable-3DGS`、`STG`、`FlowGS`、`HGS` 共 11 条属同名误配，需人工判定。
其中 `FlowGS` 与 v0.8.4 新收录的 `Bi-FlowGS` 存在重复风险，需一并处理。

### 建议 2：176 条 B 类——按三分类分别处置

- **内部标签类**（`Survey-GS-*` 等 12 条）——作为分类锚点使用，但指向了不相关综述，建议改为独立字段，不占方法计数；
- **描述性命名类**（如 `Dual Contouring of SDF`）——名称由论文标题改写，属可接受别名，核对 `desc` 即可；
- **疑似虚构名类**（`AnchorGS`、`DensifyGS`、`GaussCalib`、`GS-Fed`、`PruneGS`、`NoiseGS` 等）——arXiv 无此方法名，建议删除或按所链接论文的真实名称重建。

### 建议 3：口径修正

README / README_CN / CLAUDE.md 中「zero fabrication / 零虚构」的表述，在数据修复完成前应补充限定语
（例如「arXiv 编号零虚构；名称—论文一致性修复进行中」），避免对外承诺与数据现状不符。

### 建议 4：CI 增强

`scripts/validate_knowledge_base.py` 目前只校验 ID 格式、重复项与黑名单，**不校验名称与论文是否对应**。
建议把本次审计逻辑固化为新的校验规则，对每日新增条目强制执行，防止同类问题再次累积。
可直接复用本次审计脚本（见下方）。
