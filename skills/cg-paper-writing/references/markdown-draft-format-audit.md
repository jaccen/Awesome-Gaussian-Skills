# Markdown 工作稿投稿前格式审计与 P0 机械修复

> 用途：对 CG 论文的 Markdown 双语工作稿（LaTeX 排版前的源稿）执行投稿前格式硬指标审计，并执行五类 P0 机械修复（批注剥离 / 摘要瘦身 / 引用重排 / 孤儿图补引 / 主文-补充切分标注）。与 latex-source-hygiene.md 互补：本文件管 LaTeX 排版前的工作稿，彼文件管 LaTeX 源码。
> 触发场景：格式评审报告产出 P0 清单后用户要求执行修复（如「先执行 P0-1~P0-5」）；或投稿前对工作稿做最后一轮格式核查（「投稿前格式核查」「清理批注」「引用重排」「格式+创新性评审」的格式侧）。
> 整理日期：2026-09-27（源自某 CVPR 投稿稿件的格式评审与 P0-1~P0-5 中英双稿同步修复实战，终检全部通过）

## 一、格式硬指标审计清单（CVPR/ICCV/ECCV 工作稿）

| 检查项 | 规范 | 检测方法 |
|---|---|---|
| 摘要词数（EN） | 150–250 词 | 提取 `## Abstract` 至下一个 `---` 之间文本，去 span 标签后按空白分词计数 |
| 摘要引用 | 0 处 | 摘要内匹配 `\[\d+\]` |
| 引用编号顺序 | 按正文首次出现顺序 1..N 严格连续 | 扫描 References/参考文献 标题之前的正文，按首次出现记录每个 [n]（组合 [a, b] 拆开逐个记） |
| 孤儿图/表 | 图表清单每项须在正文（清单节之外）至少引用 1 次 | 对每个 "Figure N"/"Table N"/"图N"/"表N" 在去除清单节后的正文区计数；用 `(?![0-9])` 防止 Figure 1 误计 Figure 10 |
| 批注残留 | 0 处彩色 span | 匹配 `<span` 计数。工作稿颜色惯例：蓝=审读意见、红=新增内容、紫=修订说明 |
| 匿名性 | 无作者/机构/致谢 | 人工核对抬头与文末 |
| 篇幅容量 | 主文 ≤8 页 | 图表总数对照经验上限（主文约 12 图 + 8 表），超出须做主文/补充切分 |

审计产出按 P0（不修不能投）/ P1（强烈建议）/ P2（可选）分级，交用户决策执行范围；用户常只要求先执行 P0。

正文引用首现顺序扫描（已验证）：

```powershell
$body = $content.Substring(0, $content.IndexOf('## References'))
$order = New-Object System.Collections.Generic.List[string]
foreach ($m in [regex]::Matches($body, '\[([0-9][0-9,\s]*)\]')) {
  $nums = [regex]::Matches($m.Groups[1].Value, '\d+') | ForEach-Object { $_.Value }
  foreach ($n in $nums) { if (-not $order.Contains($n)) { $order.Add($n) } }
}
```

## 二、P0-1 批注剥离：两类 span 处置相反

1. **正式内容标色**（修订后的定稿文本被标色）→ 只删 `<span...>` 与 `</span>` 标签，**保留文本**。
2. **过程性旁注**（对内部审稿流程的说明，非论文内容）→ **整段删除**。

判定规则（实测归纳）：
- 标题下方的 Title review note / 标题审读意见 → 删除
- 参考文献条目末尾的著录更正说明（"Replaces the earlier..."、"原条目仅有裸 URL，已按软件引用格式补全..."、"新增引用暂列于文献表末，定稿时按正文出现顺序统一重排编号"）→ 删除
- 摘要/正文中被标色的定稿表述（负结果披露、指标口径说明）→ 去标签保留
- **局限性章节的 "pending audit"/"待审计" 协议差异披露 → 保留**。这是正式学术声明（如实披露两套消融协议未对齐），不是修订批注；误删会破坏论文的诚信表述。终检时此类披露不计入批注残留。

## 三、P0-2 摘要瘦身（超限摘要压缩策略）

- 保留头条统计 ≤3 组：主消融效应量+p 值、闭环收益+检验方式、延迟/加速比。
- 负结果细节压缩为一句（如 "instruction conditioning yields no detectable benefit; we report this negative result"），删除次要统计（推理诊断数值、PSNR 分档明细）。
- 应用价值铺陈段删除或压成半句并入结论句。
- 中英同步：EN ≤250 词为硬约束；CN 无硬性字数但须与 EN 句级对应同步删减，避免两稿口径漂移。

## 四、P0-3 引用重排：占位符两步法（防链式替换）

**坑**：按映射直接顺序替换 `[11]→[12]` 后，`[12]→[13]` 会把刚改出来的 [12] 再次命中，产生连锁错误；PowerShell 闭包/MatchEvaluator 混用两趟替换有作用域风险（实测翻车）。

**正确做法（已验证）**：
1. 扫描正文（References/参考文献 标题之前），按首次出现顺序建立 旧→新 编号映射（组合引用拆开逐个记录）。
2. 第一步：把每个 `[n]`（含组合形式）替换为唯一占位符 `XCITE{n}X`。
3. 第二步：按映射把 `XCITE{n}X` 逐一替换为新编号。
4. 参考文献列表按新顺序重建条目并重编号。
5. 验证：正文引用首现顺序 = 1..N 严格连续；文献条目 1..N 连续；零孤儿条目、零未引用。

```powershell
# 第一步：[n]（含组合 [a, b]）→ 占位符
$t1 = [regex]::Replace($body, '\[([0-9][0-9,\s]*)\]', { param($m)
  $nums = [regex]::Matches($m.Groups[1].Value, '\d+') | ForEach-Object { $_.Value }
  '[' + (($nums | ForEach-Object { "XCITE${_}X" }) -join ', ') + ']' })
# 第二步：占位符 → 新编号（尾部 X 锚定，XCITE1X 不会误匹配 XCITE15X）
foreach ($k in $map.Keys) { $t1 = $t1 -replace [regex]::Escape("XCITE${k}X"), $map[$k] }
```

全文执行前先在小样本（如 `see [15, 16] and [22] and [11]`）验证映射正确。

**中英双稿注意**：两稿正文引用首现顺序可能不同（实测某方法名 EN 首现第 11 位、CN 首现第 12 位），须各自独立扫描建映射，禁止复用同一映射。

**重构后必须复检（P2 级陷阱）**：任何改变引用出现位置的内容重构（Related Work 小节合并精简、段落挪移、引用句删改）都会改变首现顺序——实测 EN §2 由 4 小节并为 3 小节后 [8]↔[9]、[11]↔[12] 互换；CN §2 由 6 并 3 后 [13] 从第 13 位漂移至第 18 位。因此 P0-3 重排不是一次性动作：每完成一轮章节重构，必须重跑首现顺序扫描，发现断裂即重执行占位符两步法重排，直至 1..N 严格连续。

## 五、P0-4 孤儿图补引

- **检测脚本自校验**：变量名/作用域错误会导致所有图计数为 0 的假阳性「全部孤儿」（实测踩坑）。先对已知被引用的图（如 Figure 1）跑一遍确认非零，再信任批量结果。
- 表同样检查：模型复杂度表（Table 1）最常被漏引——常位于独立小节且无正文引用句。
- 补引位置与句式：图所在小节的解读段末尾，"See Figure N for ..."，内容须与该图实际内容对应（渲染配置图引在渲染节、逐种子分解图引在种子分解段）。
- 中英双稿孤儿图集合可能不同（CN 有图注引用块 `> **图N**：` 而 EN 无），须分别检测、分别补引。

```powershell
$bodyText = [regex]::Replace($content, '(?s)## Figure List.*$', '')   # 去掉清单节再计数
$cnt = ([regex]::Matches($bodyText, [regex]::Escape('Figure 7') + '(?![0-9])')).Count
```

## 六、P0-5 主文/补充切分（Markdown 阶段做法）

正文物理搬移属 LaTeX 排版阶段；Markdown 工作稿阶段**不搬移内容**，只做标注与计划：

1. 补充材料小节标题加 `*(Supplementary)*` / `（补充材料）` 标记。
2. 文末（结论后、图表清单前）插入「主文/补充材料切分说明」小节：列主文保留章节、主文图表上限、补充章节与图表。
3. 经验切分（CVPR 8 页）：主文约 12 图 + 8 表；附录图（A 系列）全部进补充材料；诊断性表格（逐轴分析、双峰分布、逐任务渲染分解）进补充材料。
4. 中英双稿章节编号不同步（实测两稿对应小节的编号体系完全不同），切分标注须按各稿实际结构映射，不可按编号硬套。

## 七、执行顺序与终检

**顺序**：P0-1 批注剥离 → P0-2 摘要瘦身 → P0-3 引用重排 → P0-4 孤儿图补引 → P0-5 切分标注 → 终检。理由：剥离批注后正文才干净；摘要瘦身若增删引用须在重排前完成；补引句不涉及引用编号；切分标注放最后避免编辑冲突。

**终检清单**：
- 残余 `<span` = 0（EN/CN 分别验证）；审读意见关键词 = 0；"pending audit" 类正式披露保留且不计残留
- 引用首现顺序 1..N 严格连续（EN/CN 各自验证，含组合引用）
- 孤儿图 = 0；全部表格有正文引用
- 摘要达标（EN ≤250 词；CN 与 EN 句级对应）
- 章节结构完整（标题层级、行数变化合理）
- 修复前备份原稿至 .temp/（带日期），修复后对照备份抽查关键位置
- 章节重构（P2 级精简/合并）完成后：重跑引用首现顺序扫描，断裂则重执行 P0-3 占位符两步法重排
- .tex 重新生成后：bibitem 数 == 文献条目数且编号 1..N 连续（防转换边界静默丢条，见第八节）

## 八、MD→LaTeX 转换边界检查（P2 排版阶段）

> 沉淀来源：某稿件 MD→LaTeX 转换实战（2026-09-27）——转换后 bibitem 数比文献条目数少 2 条，转换脚本零报错，靠转换后核验才发现。

工作稿定稿转 .tex 时，转换边界存在两类静默丢失，必须核验：

1. **参考文献行尾空白 → bibitem 静默丢失**：条目行尾多余空格会使「行尾非空白」型提取正则（如 `^\[(\d+)\]\s+(.*\S)$`）失配，该条 bibitem 被无声丢弃（实测两条条目因行尾空格丢失）。处置：转换前批量去除参考文献区行尾空白；转换后核对 bibitem 编号 1..N 连续无缺失。
2. **MD 改动后 .tex 必须重新生成**：.tex 是派生产物，工作稿任何后续修改（含 P1/P2 内容补强）后重跑转换脚本，禁止 MD 与 .tex 双头手工维护。重跑后核对五项：bibitem 数、表格数、摘要词数、span 残留 = 0、Supplementary 标注保留。

```powershell
# 转换后核验 bibitem 完整性（N 为文献总数）
$bibitems = $tex | Where-Object { $_ -match 'bibitem\{r(\d+)\}' } | ForEach-Object { $Matches[1] }
$missing = 1..$N | Where-Object { $_ -notin $bibitems }   # 非空即转换边界丢条
```
