# 3DGS Paper Writing Blueprint — 3DGS 论文撰写蓝图

> **定位**：research-expert-team 程序层的 **3DGS 专属骨架扩展**。分工（自洽融合约定）：通用方法论（选题引擎/审稿预期/实验模式编号）归 `methodology-core.md`；3DGS 标杆案例证据归 `mp-3dgs.md` / `mp-spatial.md`；章节级写作模板与符号表归 `cg-paper-writing`（`writing-*.md` / `symbols-terminology.md`）——**本文件管 3DGS 论文的骨架落位程序与领域写作铁律**，与三者互引不重复。
> **使用时机**：写或改 3DGS 方向论文初稿时（R2 贡献声明定稿后进入写作，R6 框架合规期逐节核对，R4 润色期回查动机升维与符号统一）。
> **来源说明**：骨架程序经 15 篇标杆深读验证（`mp-*.md`），并由用户提供的 3DGS 写作方法论补充实例化（2026-10-15 融合）。

## 1. 写作三铁律（3DGS 论文区别于泛 CG 论文的部分）

### 1.1 动机升维——避开"调参感"

审稿人判断"工程报告 vs 研究论文"的第一信号就是动机的层级。任何超参/阈值/工程修改必须升维为**机制级策略**再写。

**四步转写程序**：
1. 写出你实际做的工程修改（如实：改了什么阈值、什么调度、什么参数）；
2. 反问：这个修改在什么场景下修复了什么失败模式？（找不出失败模式 = 该修改可能不配当贡献，降级为实现细节）；
3. 为修复**原则**命名（几何曲率引导 / 表面感知 / 时空连续 / 频率感知…）；
4. 套模板句式落地。

**弱→强转写对照**：

| 层级 | 表达 |
|---|---|
| ❌ 弱（调参感） | "我们修改了点云分裂的阈值，得到了更好的效果。" |
| ✅ 强（机制级） | "传统的密度自适应控制（Adaptive Density Control）在应对无纹理区域时会导致过拟合。为此，我们引入了一项基于几何曲率引导（Curvature-guided）的致密化策略，从根本上优化了高斯基元的空间分布。" |

**模板句式**：`传统的 [机制名] 在 [场景] 下导致 [失败模式]。为此，我们引入基于 [原则] 的 [策略名]，从根本上优化 [目标量] 的空间分布/行为。`

- 审稿人映射：methodology-core **D1**（设计任意性）与 **D7**（机制拼凑）的 preempt；程序本体见 core **B.5-8**。
- 标杆印证：3DGS 原版把 clone/split 写成"欠重建 vs 过重建 + view-space 梯度信号"的机制叙事（`mp-3dgs.md` §1.2）；SuGaR 从"理想表面分布"反推正则（`mp-3dgs.md` §3.1）。

### 1.2 符号系统的绝对统一

3DGS 涉及大量空间变换与投影，符号混乱是审稿人最容易抓的低级把柄。

**程序**：
1. 论文前半部分（Preliminary 或 Notation 小节）集中定义全部核心符号：中心 μ∈ℝ³、协方差 Σ、缩放 S、旋转 R、不透明度 α、球谐系数（颜色）c/SH；
2. 全文（含图注、表格表头、附录、补充材料）绝对统一——一处用 σ 表示 opacity、另一处用 α，即前功尽弃；
3. 初稿完成后做一次**全文符号扫描**（逐符号 grep 检查是否有变体写法）。

**执行方案**：直接使用 `cg-paper-writing/references/symbols-terminology.md` 的标准符号表（G/μ/Σ/R/S/α/c/SH/T 及投影 J、Σ'），**不另立标准**——这是与 cg-paper-writing 的融合点；程序本体见 core **B.5-9**。

### 1.3 痛点→资源评测映射

审稿人非常看重 3DGS 的"固有缺陷"是否真正得到解决：**实验必须至少包含一个资源维度的对比（FPS / VRAM / MB / Minutes），仅报 PSNR/SSIM/LPIPS 不够**。

**3DGS 固有缺陷库**（痛点→创新路线→必报维度）：

| 固有缺陷 | 典型修复路线 | 必须报告的维度（质量之外至少一列） |
|---|---|---|
| 大规模场景存储爆炸 | 剪枝/量化/压缩（LightGaussian 路线） | Size(MB) + 压缩比 + FPS/质量保持 |
| 动态场景拓扑伪影 | 变形场/4D 表示（4DGS 路线） | FPS@分辨率 + 存储 + 训练时间 |
| 无界场景背景稀疏 | 背景建模/层级表示（外球背景建模、Scaffold-GS 锚点路线） | 远场 PSNR + FPS + 内存 |
| 多尺度混叠/锯齿（变焦退化） | 多尺度滤波/抗锯齿（Mip-Splatting 路线） | 各尺度 PSNR + FPS |
| 无纹理区域过拟合/欠重建 | 几何/正则引导致密化（曲率引导、表面感知类正则） | 几何指标 + 高斯数量 + PSNR |
| Gaussians 不贴表面/抽不出 mesh | 表面对齐正则+绑定精化（SuGaR 路线） | mesh 质量 + 渲染 PSNR + 提取时间 |
| COLMAP 初始化依赖 | 鲁棒/免标定初始化（DUSt3R 路线） | 收敛鲁棒性 + 质量 vs 初始化质量曲线 |
| 训练/渲染算力开销 | 编码/光栅化优化（INGP 路线） | Training time + FPS + VRAM |

- 实验模式映射：core **C4**（五资源口径配对表：PSNR/SSIM/LPIPS + FPS + VRAM + MB + Minutes）与 **D5**（效率口径透明）；铁律来自 Comparison Fairness Protocol（`cg-paper-writing` v3.3.0）。
- 标杆印证：3DGS 原版六列大表（3 质量+3 资源，`mp-3dgs.md` §1.4）、4DGS 四列同表+存储、INGP Pareto 扫描（`mp-spatial.md` §2.4）。

## 2. 五章节落位表（3DGS 论文骨架，逐节程序）

### 2.1 Introduction——四段式弧线

| 段 | 功能 | 写作要点 |
|---|---|---|
| P1 背景引入 | NVS 发展 → NeRF → 3DGS 定位 | 落点句：3DGS 是当前**兼顾实时渲染与高画质**的 SOTA（这是所有增量论文的公共前提，一段带过即可） |
| P2 指出痛点 | 3DGS 在特定场景/任务下的致命缺陷 | 从 §1.3 缺陷库选**一个**深挖，不贪多；痛点要"致命"级（存储爆炸/拓扑伪影/背景稀疏），不是"略有不足" |
| P3 核心动机 | "In this paper, we propose..." | 一两句高屋建瓴概括创新；三类创新路径任选其一：引入某种**正则化** / 改变**高斯表示形式** / 提出新的**光栅化管线** |
| P4 贡献总结 | 三条 bullet | 固定句式：①我们指出了 3DGS 在 XXX 方面的限制 ②我们提出 XXX（方法名），通过 XXX 解决该问题 ③实验证明在 XXX 指标达 SOTA，且**保持/提升了实时渲染速度**（实时性句是 3DGS 论文的身份证明，不可省） |

- 骨架映射：core **T3**（范式/最小方法骨架）的增量论文变体；开题句式用 core **A.1"革命遗留问题"**变体。
- 案例印证：SuGaR 引言即此四段式的标准实现（`mp-3dgs.md` §3.1）。

### 2.2 Related Work——三分类护城河

不罗列论文，分类评述 + 每小节末尾放定位句：

1. **NeRF 及其演进**：一笔带过，作大背景（约 3-4 句）；
2. **3DGS 及其变体**：重点区——梳理近 1-2 年与你最相关的分支（做动态的、做压缩的、做抗锯齿的，对应 §1.3 缺陷库中的修复路线）；
3. **领域特定技术**：你特定方向的技术线（如做 3DGS 物理模拟，则写图形学物理模拟工作一节）。

每小节末尾：一句"**现有工作与本文的本质不同**"（机制层面，不是形容词层面）。
- 映射：core **B.3** 三组递进式；分组主题清单与段落模板用 `cg-paper-writing/writing-related-method.md`（融合点，不重复）。

### 2.3 Method——总-分结构

| 小节 | 内容 | 写作要点 |
|---|---|---|
| 3.1 Preliminary | **必须包含**：经典 3DGS 数学表述三件套 | ①高斯函数 G(x)=exp(-½(x-μ)ᵀΣ⁻¹(x-μ))；②3D→2D 投影 Σ'=JWΣWᵀJᵀ；③α-blending 渲染 C=ΣᵢcᵢαᵢΠⱼ₌₁ⁱ⁻¹(1-αⱼ)。体现理论基础扎实 + 为自己的公式铺符号（与 §1.2 符号统一联动） |
| 3.2 Overview | 一幅高清 Pipeline 图 + 一段总览 | 输入（点云/图像）→核心模块→输出（渲染图）全程一图；后续模块小节都回指该图 |
| 3.3 Module A | 核心创新点 1（如"基于几何感知的致密化"） | 每个模块先动机升维叙事（§1.1 四步程序），再给具体公式推导 |
| 3.4 Module B | 核心创新点 2（如"时空连续性损失函数"） | 同上；模块数≤2 为宜，贪多必被 D7"机制拼凑"打回 |
| 3.5 Optimization | Total Loss | 标准形式 ℒ_total = ℒ_rgb + λ₁ℒ_dssim + λ₂ℒ_novel——每个 novel loss 一行定义+一句动机（升维后的），权重在实验节交代 |

- 映射：core **B.5-7**（跨社区铺路——Preliminary 同时服务图形学/视觉读者）；4DGS 的 §3 Preliminary 即此模板的样板（`mp-3dgs.md` §2.3）。

### 2.4 Experiments——四表规范

**4.1 Setup**：
- Datasets：Mip-NeRF360 / Tanks&Temples / Deep Blending / Blender（合成）或任务专属数据集；**完全继承上游协议**（core C15：可比性=说服力）；
- Implementation Details：PyTorch + 定制化 CUDA 算子、学习率、迭代次数（7k/30k）、显卡型号（RTX 4090/A100）——core **D5** 效率口径透明的逐项清单。

**4.2 Main Results（定量+定性双轨）**：
- 表格列规范：PSNR / SSIM / LPIPS **+ Size(MB) + FPS**（§1.3 至少一维资源），自家方法**加粗**；跨族方法先分组再进表（有 mesh vs 无 mesh、单目 vs 多目阵列）；
- 定性图规范：**放大的局部细节图（zoom-in patches）**，用虚线框或箭头指出经典 3DGS 产生的伪影（artifacts / floaters），你的方法干净且锐利——"负结果图当设计动机"（core E-4）在 3DGS 论文里的标准形态。

**4.3 Ablation**：
- 三行式起步：`w/o Module A` / `w/o Loss B` / `Full Method`——**每一个 Module、每一个 novel Loss 都要有独立消融行**（顶刊最看重的一块）；
- 进阶叠加 core **C10**（双工作点 7K/30K）、**C11**（机制分层结论：哪个崩、哪个边际）。

### 2.5 Conclusion & Limitation

- Conclusion：总结全文，重复强调方法有效性与实时性保持；
- Limitation：**诚实指出不足**——主动提出不会被拒，反而展现学术诚实、降低审稿人抓把柄的概率。写法按 core **B.4**（现象+机制解释+修复路径），3DGS 常见限制库见 §3。

## 3. 3DGS 限制库（诚实限制句式素材）

| 限制 | 句式骨架（现象+机制+接口） |
|---|---|
| 极端光照敏感 | "对极端光照变化仍敏感——SH 低阶系数在训练视角未覆盖的角度区域外推失真；引入 HDR 先验是潜在路径" |
| 初始化依赖 | "依赖高质量的 COLMAP/SfM 初始化——稀疏点噪声导致致密化误触发；与 feedforward 几何基础模型（DUSt3R 谱系）结合是自然接口" |
| 高斯数无上界 | "百万级高斯的存储/传输成本随场景规模线性增长——本方法的压缩比在更大场景下的保持性待验证" |
| 近似 α-blending | "tile 级排序的 α-blending 在 splat 显著大于像素时引入近似误差（3DGS 原版已承认的共享病灶，挂其引文）" |
| 动态拓扑突变 | "变形场假设局部平滑运动，拓扑突变（出现/消失物体）仍产生伪影" |

原则：共享病灶挂领域引文（不是你的错），自家可改进项写成 future work 的具体接口（core B.4 / D8）。

## 5. 投稿前快速检查清单

- [ ] 每个工程修改都完成动机升维转写（全文无"调参感"句子残留）？
- [ ] 符号表扫描：μ/Σ/S/R/α/SH 在正文、图注、表格、附录中写法一致？
- [ ] 资源维度：至少 FPS/VRAM/MB/Minutes 之一与三个质量指标同表呈现？
- [ ] 定性图：zoom-in patches + 虚线框/箭头标注 3DGS 伪影？
- [ ] 消融覆盖每一个 Module 与每一个 novel Loss（w/o 行齐全）？
- [ ] Introduction P4 第三贡献含"保持/提升实时渲染"句？
- [ ] Preliminary 含 3DGS 数学三件套（G/Σ'/α-blending）？
- [ ] 限制节每条 = 现象 + 机制 + 修复路径，共享病灶挂领域引文？
- [ ] 基线与数据集完全继承上游协议（Comparison Fairness Protocol 核查）？
