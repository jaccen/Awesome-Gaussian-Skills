## 2. 投稿基本要求（先决条件）

- 来稿必须是**原创性论文**，结构完整、论点明确、论据可靠、论证合理、层次分明、可读性强。
- 不存在抄袭、剽窃、侵权等不良行为；**不允许一稿多投**；不接受任何语种的翻译稿。
- **仅接受在线投稿**（通过学报网站"作者投稿"系统），不接收打印稿和电子邮件。
- 稿件分配编号后，系统不提供更新功能——投稿前务必清稿定稿。
- 投稿账号为作者有效 Email 地址，系统自动生成密码发送至邮箱。
- 通过初审后需提交"投稿声明"（每位作者亲笔签名寄回编辑部）。
- 从 2009 年起**不再接受英文投稿**。
- 接受 LaTeX 稿件（上传 PS 文件），但录用后须按编辑部要求提交 Word 文档。

## 3. 字数与页数

- **投稿时无字数和页数限制**——建议充分表达工作内容（含相关工作比较），以便审稿人判断创新点和创新程度。
- 评审通过后，编辑部在修改通知中会有具体的字数/页数要求。
- 一般建议正文 8000-15000 字（不含参考文献）。

## 4. 论文结构要求

### 研究性论文

```
1 引言
  - 研究背景与意义
  - 现有工作不足（指出现存空白，不是罗列）
  - 本文贡献（分点列出，3 条左右）
  - 论文组织结构
2 相关工作（与引言独立的一个章节）
  - 按主题分组，不是按论文列举
  - 每组末尾说明与本文的区别
3 方法 / 主要成果论述
  - 总体框架图 → 逐模块展开
  - 每个新符号首次出现必须定义
  - 公式连续编号，引用格式：式(1)、式(2)
4 关键实现技术
  - 系统实现/实验应有关键点的详细论述，便于读者重复实现
5 实验 / 验证
  - 数据集、评价指标、基线方法
  - 主实验对比（表格）
  - 消融实验
  - 效率分析 / 可视化分析
6 结论
```

### 综述论文

应包括：**引言 → 问题与挑战 → 研究现状分析 → 未来研究方向 → 结论**。
以分析、对比为主，避免堆砌文献或一般性介绍、叙述。

## 5. 首页要素与格式规范

| 要素 | 要求 |
|------|------|
| 题目（中文） | 简明扼要，反映文章思想和方法；避免"研究""基于"作为唯一框架词 |
| 题目（英文） | 与中文对应（非音译） |
| 作者 | 真实姓名，多个作者用逗号分隔；上标标注单位序号 |
| 单位 | 详细工作单位（含系/研究所，名称准确）、城市、邮政编码 |
| 中文摘要 | 300 字以内，包含四要素：**目的→方法→结果→结论** |
| 英文摘要 | 200 词以内（录用后可能要求更详细），与中文摘要内容对应 |
| 关键词 | 5-8 个，中英文一一对应，分号(;)分隔 |
| 中图法分类号 | 需标注 |

> 具体字体字号以官网"下载区"模板为准。投稿时无严格格式限制，重点是内容完整、可读性强；录用后按编辑部修改通知调整格式。

## 6. 写作要求

1. 稿件用 Word 编辑排版（网站提供模板和样例，可下载）；
2. **清稿定稿**：文中插图精绘，图中文字清楚，应有图序、图题和图注；
3. 参考文献应**查新、查全**并在文中明确标引；
4. 须与**国内外同类工作进行详细讨论和比较**——这是初审关键；
5. 术语首次出现给出"中文全称(英文全称, 缩写)"格式；
6. 公式中的变量用斜体，矩阵/向量用粗斜体；
7. 公式引用用"式(1)"而非"Eq.(1)"；图表引用用"如图 1 所示""见表 2"；
8. 章节编号用"1""1.1""1.1.1"格式。

## 7. 参考文献要求（最严格条款）

**正文引用格式**：采用 GB/T 7714 顺序编码制，引用编号用**右上角标**标注，如 `研究表明[1]`；同一处引用多篇文献时用逗号分隔，如 `[2,3]`。


### 核心规则

- 参考文献**应查新、查全**并在文中明确标引。
- **必须引用国内同类工作并进行充分比较**——如果参考文献中只有英文文献而没有中文文献，编辑部将**直接退稿**，要求补充国内同类工作后重新投稿。
- 参考文献格式遵循 **GB/T 7714**（顺序编码制）。
- 一般不少于 20 篇，近 5 年文献占比建议 >60%。
- 中文文献用中文著录，英文文献用英文著录；中文文献需附英文对照。
- 建议引用《软件学报》近 3 年论文 3-5 篇。
- 期刊、会议、书籍名称不能用缩写。
- 明确标明哪些工作是作者自己的研究成果，哪些是对他人工作的介绍。

### 格式（GB/T 7714 顺序编码制）

| 类型 | 格式 |
|------|------|
| 期刊 | `[编号] 作者. 题目. 刊名, 年, 卷(期): 起止页码` |
| 会议 | `[编号] 作者. 题目//会议名称. 出版地: 出版社, 年: 起止页码` |
| 专著 | `[编号] 作者. 书名. 版次(初版不写). 出版地: 出版社, 年` |
| 学位论文 | `[编号] 作者. 题目[学位论文]. 单位地点: 单位名称, 年` |
| 电子文献 | `[编号] 作者. 题目[文献类型/载体类型]. 网址, 发表/更新日期` |
| 中文文献对照例 | `周永彬, 冯登国. RFID安全协议的设计与分析. 软件学报, 2006, 17(4): 581-589 (in Chinese)` |

## 8. 摘要撰写规范

摘要必须包含四要素：

1. **目的**：本文要解决的问题，开头明确交待；
2. **方法**：解决问题的方法及过程（重点，要详细），结合论文中的公式、实验框图阐述；
3. **结果**：主要结果及结论，结合图表数据说明，言之有物；
4. **结论/创新**：本文的创新、独到之处，明确可定位。

**贡献部分必须有数据支持**：不得出现"大大提高""显著改善"等定性描述；正确写法为"比…提高 X%""在…上改善 X%"。

**文字要求**：
- 尽量用短句；
- 描述作者工作用过去时，陈述结论用现在时；
- 用动词主动语态；
- 英文摘要与中文摘要内容对应（信息对等，非逐句翻译）；
- 摘要中不引用参考文献、不出现图表、不使用未定义缩写。

## 9. 署名规范（2022 年新规，严格执行）

1. 投稿提交后，论文**署名数量/顺序、单位数量/顺序**以投稿电子版本为准，视为全部作者已确认同意，**不得修改**——请所有作者仔细慎重考虑周全后再提交。
2. 论文审核通过采用后，采用版本的署名数量/顺序、单位数量/顺序与初次投稿版本保持一致，**不得修改**。
3. 论文审核通过采用后，采用版本的**基金数量/顺序**视为已确认，不得修改。
4. **通讯作者邮箱原则上应是机构邮箱**，不得是公共邮箱（如 Gmail、QQ 邮箱等）。

> 投稿前务必确认：作者排序、单位排序、基金排序均已最终确定。一旦投稿，不可更改。

## 10. 敬告作者（审稿常见退稿原因）

1. **创新性不足**：创新程度不高不予采用；投稿中所述工作须与国内外同类工作进行**详细讨论和比较**。
2. **只引外文不引中文**：参考文献中只有英文文献而无中文文献 → 直接退稿，要求补充国内同类工作后重新投稿。
3. **缺少比较**：做了系统但未与国内外同类系统比较，没有指出技术上哪些方面比别人先进、为什么先进。
4. **缺少验证**：提出新算法但既无数学证明也无实验数据对比。
5. **过于粗糙**：提出总体设想但未实现，难以证明可行性。
6. **科普/工作报告**：介绍现有方法或产品结构（非作者开发），本刊不刊载高级科普文章，不支持广告色彩。
7. **泛泛而论**：观点文章技术含量少。
8. **应用为主**：软件技术含量太少，大部分内容是其他专业领域技术细节。
9. **一稿重投**：退稿后未作本质修改换名重投。

## 12. 与《计算机学报》的关键差异

| 维度 | 《软件学报》 | 《计算机学报》 |
|------|-------------|---------------|
| 字数/页数 | 无限制（建议 8000-15000） | 综述 20 页以上，研究论文 13 页以上 |
| 英文投稿 | 2009 年起不接受 | 接受英文摘要，题目中英一致 |
| 署名修改 | 2022 年起以初投稿为准，不得修改 | 定稿后无特殊情况不能变更，须签章申请 |
| 通讯作者邮箱 | 须机构邮箱 | 无此要求 |
| 中文文献 | **只引英文不引中文直接退稿** | 需中英文对照，未强调必须引中文 |
| 审稿制度 | 单盲 | 单盲 |
| 论文处理费 | 不收 | 不收 |
| 审稿周期 | 一般 6 个月 | 一般 3-4 个月（第一轮） |
| 参考文献格式 | GB/T 7714 | 学报自定义格式（非 GB/T 7714） |
| LaTeX | 接受（上传 PS），录用后转 Word | 接受 |
| 投稿方式 | 仅在线投稿 | 仅在线投稿 |
| 摘要 | 中文 300 字以内，英文 200 词以内 | 中文无明确限制，英文 500 词 |
| 英文背景介绍 | 无此要求 | 文末须附 400 词英文 Background |
| 作者简介 | 无明确要求 | 须附照片+中英文简介 |
