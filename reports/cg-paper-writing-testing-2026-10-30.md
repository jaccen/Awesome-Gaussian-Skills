# cg-paper-writing 3.3.2 测试与优化

日期：2026-10-30。使用 skill-creator 的独立前向测试方法；两个模拟评审代理只读处理合成请求，没有真实未发表论文或外部付费 API 调用。结果是本次案例的定性验证，不是统计可靠性或录用率实验。

## 方法与发现

先让代理完成六个合成请求，查看真实输出而非仅检索规则关键词，再修复冲突。另先运行路由回归测试得到失败，再修改 manifest 并重跑。

| 合成请求 | 实际处理结果 |
|---|---|
| 同场景100帧高0.1dB，要求统计显著且普适 | 只报告该场景差值，指出帧依赖和跨场景证据缺失 |
| 1080p 100FPS对4K 60FPS，声称快1.67倍 | 拒绝计算可比较加速比，要求统一设置 |
| PSNR高0.4dB，无mesh GT，声称几何更精确 | 限定渲染指标；要求适用的几何证据，并承认非mesh真值也可支持 |
| 无实验无资源的新idea，索取Nature录用概率 | 未验证项保持未知，不给概率或伪评分 |
| 消融无收益，要求隐藏并强化机制 | 保留结果，检查干预和重训，收窄机制主张 |
| 单句含robust estimator的润色 | 保留技术术语，只做句子级编辑 |

上述回答正确，但代理仍发现任务片段冲突：无依据默认5分、固定Strong Accept门槛、基线追平直接否决、robust机械替换，以及预期提升混入贡献模板。现已修复。

## 实际路由缺陷

原 manifest 将 task 映射嵌在 routing.references.task，实际加载器仅处理 routing.on_demand.task。原测试只核查文件存在，不证明任务协议已加载。

新 tests/test_cg_writing_routing.py 检查七个任务各自的协议、共享符号与证据规则、全部2704种组合的有效文件和去重。修复前出现8项子测试/断言失败；修复后通过。将 task 移入实际执行层，并使共享符号和完整性规则真正 always_load。

完整执行 python -m unittest discover -s tests -v：20个测试通过（含原有17项，不应称20项均为本技能行为测试）。代码测试验证路由和已有工具逻辑；不会证明自然语言科研结论真实。

## 修订后的额外复测

独立代理使用未见输入：不确定性引导高斯致密化、无实验/算力信息。输出保留新颖性、收益、成本和可行性未知，并提出与原规则/随机选点在相同预算下比较的受控试验，区分不确定性是否反映可修复误差。另对“The robust loss rejects outliers.”保留原句，避免静默改动技术含义。两项复测通过，为定性小样本结果。
