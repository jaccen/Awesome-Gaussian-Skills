

# 专利说明书撰写模板与规范

## 一、总体要求

- 说明书应使**本领域技术人员**不需创造性劳动即可实施
- 充分公开：技术方案、具体实施方式、技术效果缺一不可
- 与权利要求书呼应：说明书中记载的内容是权利要求的支撑基础

## 二、各章节撰写规范

### 一、技术领域

1段即可，说明发明所属或应用的技术领域。

```
本发明涉及[大技术领域]领域，尤其涉及一种[具体技术方向]的方法及系统。
```

### 二、背景技术

#### 2.1 现有技术描述

- 按**技术方向**分类列举现有方案
- 每条包含：来源标识（专利号/文献号）、技术方案概要、应用场景
- 来源需可追溯，不得虚构专利号

#### 2.2 现有技术缺陷

- 分点列举，与2.1现有技术的局限性呼应
- 突出**核心缺陷**：现有技术无法解决的问题
- 每个缺陷在第三章有对应的技术方案

### 三、发明内容

#### 3.1 要解决的技术问题

对应第二章缺陷，逐条列出本发明要解决的问题。通常1-3个。

```
为了解决上述现有技术中存在的[缺陷概述]问题，本发明提供了一种[技术主题]方法及系统。
```

#### 3.2 技术方案

**此章节与权利要求书严格对应**，按权利要求逐项展开。

撰写规则：
- 独立权利要求对应的段落直接复述权利要求内容（可稍加解释性文字）
- 从属权利要求对应的段落用"进一步地""优选地""在一些实施例中"等引导
- 每项技术特征需提供足够的实施细节

模板：
```
本发明提供了一种[技术主题]方法，包括：
[A步骤]：[详细描述]；
[B步骤]：[详细描述]；
其特征在于，还包括：
[C步骤]：[详细描述，含关键算法/逻辑]；
[D步骤]：[详细描述，含参数/条件]。

进一步地，所述[C步骤]中，[进一步限定的具体实现方式]。

优选地，所述[参数X]的取值范围为[范围]，[说明该范围的技术依据]。
```

系统类权利要求对应段落同理，将"步骤"替换为"模块"。

#### 3.3 有益效果

每个有益效果必须有**技术方案支撑**，格式：

```
本发明的有益效果包括：
（1）[效果1]：通过[技术特征]实现[效果]，解决了现有技术中[缺陷]的问题；
（2）[效果2]：...
```

禁止：空泛断言（"提高了效率"而无量化或机制说明）。

### 四、附图说明

逐图说明，格式：
```
图1是本发明实施例提供的[系统名称]系统框图；
图2是本发明实施例提供的[方法名称]流程图；
图3是本发明实施例提供的[模块名称]结构示意图。
```

附图在说明书中用fenced mermaid表示，审查阶段可用正式制图替换。

### 五、具体实施方式

**核心章节**，篇幅通常占说明书60%-70%。

#### 5.1 实施例一

对应独立权利要求，必须覆盖独立权利要求的**全部技术特征**。

模板：
```
下面将结合本发明实施例中的附图，对本发明实施例中的技术方案进行清楚、完整地描述。

实施例一

本实施例提供一种[技术主题]方法，如图X所示，包括以下步骤：

S101：[步骤A描述]
[具体实现细节，含算法、数据结构、参数配置]

S102：[步骤B描述]
[具体实现细节]

S201：[步骤C描述——特征部分]
[详细描述核心创新步骤的算法逻辑]
[关键公式，附公式编号]
[参数含义解释与典型取值]

S202：[步骤D描述]
[具体实现细节]

S301：[步骤E描述]
[输出结果的格式与用途]
```

#### 5.2 实施例二及后续

展示不同的实施方式或应用场景，可侧重：
- 不同参数范围下的实施
- 不同应用场景的适配
- 从属权利要求中进一步限定特征的实施

每个实施例需自成体系，不能简单引用其他实施例而省略有别于其的特征。

## 三、脱敏对照表

| 原始内容 | 脱敏方式 | 示例 |
|----------|----------|------|
| 业务领域名称 | 抽象为通用描述 | "医疗CT影像" → "目标图像" |
| 具体分类/标签 | 用字母编号替代 | "心房颤动" → "类别A" |
| 具体数值 | 用范围代替 | "0.75" → "预设阈值（0.5-1.0）" |
| 公司/产品名 | 删除或用"某系统" | "XX云平台" → "某计算平台" |
| 人名/地名 | 全部占位 | "张三" → "[发明人]" |
| 内部项目代号 | 删除 | "猎鹰计划" → 不出现 |

## 四、术语一致性检查清单

生成全文后，逐一核对：

- [ ] 同一技术特征在全文（权利要求书+说明书+摘要）使用统一术语
- [ ] 附图中的标注与正文术语一致
- [ ] 公式中的符号与正文定义对应
- [ ] 实施例中的参数名与3.5节描述一致
- [ ] "所述"仅用于回引前文已出现的技术特征

## 五、说明书与权利要求书对照表

生成时必须构建以下对照表（内部使用，不写入交付文件）：

| 权利要求编号 | 核心技术特征 | 说明书对应段落 | 实施方式是否充分 |
|-------------|-------------|---------------|-----------------|
| 1（独立） | 特征C、D、E | 3.2、5.1 | ✓/✗ |
| 2（从属） | 限定C的实现 | 3.2+、5.1 | ✓/✗ |
| ... | ... | ... | ... |

若某权利要求在说明书中无充分支撑，须补充实施方式后再交付。
