# Experiment Design Protocol — 3DGS 实验设计与训练调试

> 融合自 3dgs-experiment-planner + 3dgs-training-debugger。用于阶段5实验设计与分析，在用户要求"设计实验/选数据集/选基线/选指标/消融实验/训练崩溃/NaN/OOM/调试"时加载。

## 适用场景

- 为 3DGS 论文设计实验方案（数据集/基线/指标/消融矩阵）
- 训练崩溃或结果异常时诊断根因
- 回应审稿人对实验设计的质疑
- 为论文补做远程实验或核查实验声明

## 数据集推荐

### 基准选择与协议登记

数据集依研究问题选择，不存在适用于所有 3DGS/CAD/SLAM 论文的“必用”集合。先确定任务、输入条件、监督与泛化范围，再查原论文、官方数据和评测代码；以下仅为候选，不保证最新或穷尽。

| 任务 | 候选数据源 | 必须核查的协议 |
|------|------------|----------------|
| 静态新视角合成 | Mip-NeRF 360、Tanks and Temples、Deep Blending、NeRF-Synthetic | 使用的场景子集、降采样倍率、相机标定、背景和测试视角 |
| 表面重建 | DTU、Tanks and Temples | 扫描子集、遮罩、尺度、裁剪、表面对齐与官方评测脚本 |
| 大规模场景 | Mill 19、MatrixCity | 区块划分、训练/测试轨迹、跨区泛化与资源预算 |
| 动态场景 | D-NeRF、HyperNeRF、NeRF-DS | 时间/视角划分、单目或多目输入、相机和形变监督 |
| 人体/Avatar | ZJU-MoCap、THUman2.0（按任务） | 动态序列与静态扫描的区别、新姿态/新身份测试 |
| 前馈重建 | RealEstate10K、ACID | 训练数据来源、场景去重、输入视角数、跨数据集测试 |
| SLAM | Replica、TUM-RGBD、ScanNet | RGB/RGB-D、在线输入、位姿监督、轨迹对齐约定 |
| 自动驾驶 | Waymo、nuScenes、KITTI-360 | 传感器配置、动态物体、时间泄漏与空间划分 |
| 语义/语言场 | LERF 数据、SemanticKITTI（按任务） | 2D/3D标注、类别集合、开放词汇协议与监督预算 |
| 材质/重照明 | 有真实光照与材质真值的任务数据 | 光照标定、曝光、几何监督与新光照划分 |
| CAD/编辑/具身/医学/物理 | 从对应原始工作查找已发布数据 | 数据许可、可获取性、独立测试任务与适用评价 |

不得把方法名或项目名直接当作标准数据集。例如 GaussianGrasper、ManiGaussian 等应先核查其论文是否发布可复用数据和评测协议。不得凭方法库登记自动补写场景数、分辨率、venue 或结果数字。

在实验清单登记：数据版本/来源、场景列表、split、实际评测分辨率（允许逐场景不同）、预处理、排除场景及原因。区分整个数据集规模与某篇论文使用的子集；不把固定分辨率套用到所有场景。

## 基线选择

以任务、输入、监督、训练数据及计算预算匹配度选择；原始 3DGS 和 Mip-NeRF 360 适用于相关静态重建参照，不是所有任务的必比项。区分逐场景优化和跨场景前馈方法，记录预训练成本、测试时优化与辅助输入。下列名称来自历史清单，需从原论文/官方实现核验身份、最新相关性与适配条件；不得照抄 venue、奖项或性能。

### Tier 1 — 基础参照（适用时）

- 原始 3DGS（Kerbl et al., SIGGRAPH 2023）
- Mip-NeRF 360（Barron et al., CVPR 2022）

### Tier 2 — 与主张直接相关的强基线候选

- 2DGS 或 Scaffold-GS（按方法类别选）
- 一个 NeRF 变体（NeRF / Instant-NGP / Mip-NeRF）
- Proxy-GS（若声称加速）
- 2DGS（若声称几何质量）
- SparseSplat（若声称前馈效率）
- ZPressor（若声称多输入视角前馈可扩展）
- VolSplat（若声称体素对齐或多视角一致性）

### Tier 3 — 子领域候选（引用和运行前核验）

按子领域选同类别方法：
- **压缩**：LightGS / Compact-3DGS / NanoGS / MesonGS++ / GETA-3DGS
- **几何**：SuGaR / 2DGS / 2D-SuGaR
- **编辑**：Instruct-NeRF2NeRF / GOR-IS
- **训练优化**：Scaffold-GS / Structure-Aware Densification / LeGS / CAdam
- **加速**：FastGS / GEMM-GS（候选，核查论文身份、适用硬件与计时边界）
- **前馈**：FTSplat / SVGS / Pi-GS / DropAnSH-GS
- **SLAM**：Flow4DGS-SLAM / GGD-SLAM / BA-GS
- **动态**：D4RT / Color-Encoded Illumination

## 评估指标

### 质量

- **PSNR**（dB）：参考图像重建任务常用；登记色彩空间、动态范围、遮罩与按图像/场景聚合方式
- **SSIM**：参考图像重建任务常用；登记窗口与实现
- **LPIPS**：参考图像重建任务常用；登记输入归一化、实现和网络骨干
- **FID**（生成任务）：可选

### 效率

- **训练时间**（秒/分/小时）：涉及训练成本主张时报告；区分预训练、逐场景优化和预处理
- **推理 FPS/延迟**：涉及效率主张时报告；指定分辨率、硬件、批量、预热与同步方式及是否含数据传输/解码
- **显存峰值**（GB）：涉及资源主张时报告，区分训练/推理和 allocated/reserved
- **高斯点数**（M）：对高斯表示适用；不能替代实际内存和存储测量
- **模型大小**（MB）：压缩主张报告实际可解码产物，包含码本/网络/元数据；同时报告解码时间和质量–大小曲线

### 几何（若声称几何质量）

- **深度误差**（Abs Rel / RMSE）
- **法向误差**（度）
- **Chamfer 距离**（若有 GT 网格）

### 鲁棒性（若声称鲁棒）

- 跨场景方差
- 噪声输入下的指标衰减
- 稀疏视角下的指标

## 消融实验矩阵

### 必做消融

| 消融维度 | 做法 | 验证什么 |
|---------|------|---------|
| 核心模块 | 逐个去掉，看指标掉多少 | 每个模块的独立贡献 |
| 关键超参 | 在合理范围内扫，看敏感性 | 超参鲁棒性 |
| 损失项权重 | 逐项调零/翻倍，看影响 | 损失设计的必要性 |
| 数据规模 | 减少输入视角/帧数 | 数据效率 |

### 消融纪律

- 预先指定主指标、训练预算、评估集合及选择规则。调参用验证集，测试集仅用于最终评估；不能按观察到的增益筛选最终报告场景。
- 多种子用于估计优化随机性；按预算和方差确定次数，说明不可复现实验与资源限制。报告均值、离散性和每场景结果，不把同一场景的视角当成独立场景样本。
- 先定义推断对象和独立实验单位，再选择统计方法。配对方法要求同场景/同配置配对；t 检验需检查差值分布和独立性，小样本时考虑合适的置换/区间估计并披露局限。不存在“所有消融必须配对 t 检验”的规定。
- 报告效应大小和不确定性，涉及多重比较时说明控制方式；p 值不能替代实际效果，也不能把 0.5 dB 作为通用显著性门槛。
- 删除模块不总能隔离独立贡献；有交互作用时加入组合消融或析因设计，保持调参预算公平。负结果如实保留，不因不显著而删除对应发现。
- 小规模试跑用于排错和预算估计，须标记为 pilot；确认性实验使用预定完整集合，不因 pilot 中达到某个增益才选择“好看”的场景。

## 比较公平性协议（与 writing-experiments.md 一致）

所有比较方法（含基线）必须在**同一数据集、同版本、同分辨率、同 split、同评估协议**下评估。基线数字的口径无法核实时，在统一设置下重跑，**不得静默复用、转换或近似不匹配口径的数字**，不得在同一表内混合不同口径数字。

## 训练调试：症状与候选原因速查

### 崩溃类

| 症状 | 可能根因 | 诊断步骤 | 修复 |
|------|---------|---------|------|
| OOM / CUDA error | 显存不足 / 点数爆炸 / batch 过大 | 查 nvidia-smi 峰值；查高斯点数增长曲线 | 降 batch / 限制 densify 上限 / 梯度累积 |
| NaN / Inf loss | 学习率过高 / 数值不稳 / 梯度爆炸 | 查 loss 曲线突变点；查梯度范数 | 降学习率 / 加梯度裁剪 / 检查 log 运算 |
| CUDA kernel assert | 索引越界 / 形状不匹配 | 查 stack trace 定位 kernel | 核对张量形状 / 边界条件 |

### 收敛类

| 症状 | 可能根因 | 诊断步骤 | 修复 |
|------|---------|---------|------|
| Loss 平台期不降 | 学习率过低 / densify 未触发 | 查 densify 触发次数；查学习率调度 | 调 densify 阈值 / 检查 scheduler |
| 训练发散（loss 先降后升） | 自适应 densify 失控 / 损失冲突 | 查点数增长是否异常；查各损失项趋势 | 限制 densify 频率 / 调损失权重 |
| 过早收敛（PSNR 卡在低位） | 容量不足 / 正则过强 | 查点数是否过早饱和；查正则项权重 | 放宽 densify / 降正则权重 |

### 伪影类

| 症状 | 可能根因 | 诊断步骤 | 修复 |
|------|---------|---------|------|
| 大型浮点（floaters） | densify 过度 / 不透明度衰减不足 | 渲染深度图看悬浮点；查不透明度分布 | 加不透明度正则 / 周期性剪枝 |
| 边界模糊 | 高频细节不足 / 低通滤波 | 查高频区域局部 PSNR | 加高频感知损失（SignedGS 思路） |
| 残影/鬼影 | 动态场景时间不一致 | 查相邻帧差异图 | 加时间一致性损失 |
| 孔洞 | densify 不足 / 表面重建缺失 | 查深度图空洞 | 检查梯度/尺度触发条件；若梯度阈值过高阻止致密化，验证后适当降低 / 检查可见性与表面正则 |

### 分布式/检查点类

| 症状 | 可能根因 | 修复 |
|------|---------|------|
| 梯度不一致 | All-Reduce 未同步 | 检查 DDP sync 点 |
| 死 worker | NCCL 超时 / 个别 GPU 崩溃 | 查 NCCL 日志 / 降 batch |
| 检查点恢复结果不同 | 随机性未固定 / 优化器状态未存 | 固定种子 / 存完整优化器状态 |

### 新方法专项（deformable/MoE/physics/feed-forward）

- **Deformable GS**：变形场过拟合 → 检查变形正则；时间平滑性不足 → 加时序一致性
- **MoE-GS**：路由崩塌 → 检查负载均衡损失；专家死锁 → 加探索噪声
- **Physics-based GS**：物理约束冲突 → 检查物理损失与渲染损失的权重比
- **Feed-forward GS**：泛化不足 → 检查训练集多样性；推理崩塌 → 检查前馈网络容量

## 执行层说明

本协议提供实验设计方法论与调试检查清单。执行时：
- 实验设计：我按上述表推荐数据集/基线/指标，生成消融矩阵表格供用户确认
- 训练调试：用户贴出 loss 曲线/错误信息/渲染结果，先检查日志、代码和输入，按下表提出可验证的根因候选，避免把症状直接认定为根因
- 远程实验：配合 `experiment-claim-verification.md` 的 SSH-PowerShell 操作规范
- 挂机实验：用 `autoresearch` 技能（不融入本协议，因其为运行时编排能力）
