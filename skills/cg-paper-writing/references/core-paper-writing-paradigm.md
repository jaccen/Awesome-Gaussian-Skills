# 领域通用论文架构模式（Field-General Paper Architecture Pattern）

> 适用：3DGS / 三维视觉 / 计算机图形学 / CAD / 空间智能方向的范式创造、诊断改进、系统集成、基准/数据、分析/理论、综述六类论文；国际顶会与中文核心双轨。
> 定位：给"不变量 + 变体矩阵"，不给单篇论文的复制模板。任何单篇论文只作为证据，不进入规则栏。
> 证据基础（多源）：统计层来自 10 篇 CVPR 2026 及前沿 3DGS 论文共性（`top-paper-patterns.md`）；逐句层来自 3DGS、Mip-Splatting、D4RT 三篇基准（`writing-patterns-from-top-papers.md`）；方向层来自 3DGS、具身、空间智能、Agent 四方向模板（`domain-exemplar-templates.md`）；新增两篇样本 SeeLe（CVPR 2026 Highlight）与《SLAM新机遇—高斯溅射技术》（中国图象图形学报）只作为 §6 证据附录中的实例。
> 整理日期：2026-11-04

---

## 0. 三条不变量

无论写哪类论文、投哪个 venue，下面三条不变。它们是"架构"本身，其余都是可替换的变体。

### 0.1 论证链不变量

```
问题（谁的痛） → 缺口（为什么现有方法没解决） → 洞察（我们看到了什么别人没看到的）
→ 机制（我们怎么做，为什么这样做有效） → 证据（哪张图/表/实验证明） → 边界（什么时候不成立）
```

判定标准：链条上任何一环填不出来，论文就不成立。证据环填不出来，说明有 claim 无支撑；边界环填不出来，说明作者没想清楚适用条件。

### 0.2 证据不变量

每个 claim 必须有可复核的证据节点，且证据与 claim 一一对应。证据节点只有五类：主对比表、消融表、定性图、诊断图、外部引用。没有证据节点的句子，要么删，要么降格为"假设/观察"。

### 0.3 边界不变量

必须声明适用条件与失效情形。顶会论文的 Limitations 越具体越可信；中文核心的"问题与展望"承担同一职能。回避边界不会让论文更强，只会让审稿人替你写出边界。

## 1. 先分型：六类论文

写之前先判定类型。类型决定叙事主线、骨架重心和证据形态，不判定类型就直接套模板，是"被单篇论文污染"的根源。

| 类型 | 识别特征 | 叙事主线 | 骨架重心 | 多篇代表 |
|------|---------|---------|---------|---------|
| **范式创造型** | 定义新表示或新问题，后续大量工作跟随 | 旧范式有结构性成本，我们换掉它 | 问题重构 + 新表示 + 范式对比 | 3DGS（SIGGRAPH 2023）、D4RT（CVPR 2026 Best Paper） |
| **诊断改进型** | 先分析某失效机制，再给对症修法 | 症状 → 根因 → 对症组件 | 诊断节 + 组件与根因一一对应 | Mip-Splatting（CVPR 2024 Best Student Paper）、SeeLe（CVPR 2026 Highlight）、TemporalGS |
| **系统集成型** | 多组件拼装，单点新意有限但整体可用 | 管线有断点，我们用一套框架补齐 | 总览图 + 逐模块必要性 + 端到端证据 | Proxy-GS、RoboTidy、NERFIFY、CoRef-GS |
| **基准/数据型** | 现有评测缺位或数据不可得 | 没有可度量的基准，就没有可信的进步 | 缺口论证 + 构建管线 + 基准效度 | NERFIFY-BENCH、PhysAssets、CoQuad-Ref |
| **分析/理论型** | 用定理、控制变量或理论闭环解释现象 | 现象背后有可形式化的机制 | 形式化 + 归因实验 + 理论-实验闭环 | GS-VLA（Locality 定理）、GradRig（Jacobian/Hessian） |
| **综述型** | 用新分类维度重组已有工作 | 脉络 → 分类 → 比较 → 挑战与方向 | 分类主轴 + 汇总表 + 挑战展望 | 《SLAM新机遇—高斯溅射技术》（JIG）、三维视觉年度进展 |

> 混合型处理：一篇论文可以同时是"诊断改进 + 系统集成"，但主线只能有一条。主线决定摘要第一句和引言最后一段的落点。

## 2. 八环节通用架构

每节给三块：**不变量（规则）→ 类型变体（矩阵）→ 模板（槽位）**。证据栏只列多篇实例，用于说明"这个规则在多篇论文中都成立"，不是让读者照搬某篇。

### 2.1 Idea 的提出

**不变量**

1. 缺口必须可度量、可归因。不写"现有方法慢"，写"慢在哪一步、占比多少、由什么导致"。
2. idea = 缺口 × 机制。缺口是"哪里痛"，机制是"为什么这样修能止痛"，两者缺一不可。
3. 先预判证据，再动笔。说不清"哪张表能证明"，说明 idea 还没成形。
4. 单主线。一个 idea 只解决一条主线，其余作为支撑。

**五条通用选题路径**（来自 10 篇 CVPR 2026 共性统计，非单篇）

| 路径 | 问法 | 多篇代表 |
|------|------|---------|
| 效率与规模化 | 能否从 per-scene 走向摊销/免训练/即插即用 | Proxy-GS、PhysGM、E-RayZer、TemporalGS、SeeLe |
| 表示能力扩展 | 3DGS 缺哪种属性（物理/变形/声学/语义） | PhysGM、GradRig、FillGauss |
| 智能体感知底座 | 3DGS 能否作为 VLA/多机器人/评测的感知层 | CoRef-GS、GS-VLA、RoboTidy、NERFIFY |
| 基准与数据缺位 | 现有评测是否掩盖了真实能力 | NERFIFY-BENCH、PhysAssets、CoQuad-Ref |
| 理论/范式重构 | 能否用定理或新问题定义替代经验堆叠 | GS-VLA、GradRig、D4RT |

**类型变体**

- 诊断改进型：先做失效机制分析，找到"症状 → 根因"映射，再让每个组件对准一个根因（Mip-Splatting 的 erosion/dilation）。
- 系统集成型：先画出现有管线的断点，再说明每个模块补哪个断点（Proxy-GS 的 MLP 解码开销与遮挡缺失）。
- 基准/数据型：先证明"现有基准无法度量核心主张"，再设计构建管线与效度检验。
- 综述型：先找分类维度，维度要互斥、穷尽、可贯穿全章。分类维度本身就是综述的"idea"。

**模板：Idea 一页纸**

```
【谁的痛】在____场景下，____角色需要____，但当前做不到。
【缺口】现有____路线和____路线分别卡在____，共同根因是____。
【洞察】我们发现____（可量化现象/可形式化机制），这解释了为什么现有方法失效。
【主张】我们提出____，核心机制是____，同时服务____与____。
【证据预判】用____数据集/指标/诊断图证明主张，预期方向____（不写编造数字）。
【边界】当____不成立时，方法会____。
```

**证据（多篇）**：3DGS 的"sidestep"（不优化 NeRF 采样，而是取消连续表示的必要性）；Mip-Splatting 的"diagnose before cure"；SeeLe 的三瓶颈分解；Proxy-GS 的外部技术嫁接；JIG 综述的"应用输入类型"分类轴。它们形态不同，但都满足"缺口可度量 + 机制可解释"。

### 2.2 题目的命名

**不变量**

1. 三要素齐全：任务词（做什么）、技术/方法词（用什么）、差异属性（凭什么不同）。
2. 可检索：领域标准术语必须出现，不用自造词替代通用词。
3. 可证伪：卖点词（Real-Time/Unified/Alias-free/Efficient）必须能被正文证据兜住。
4. 不夸大：题目里的最高级形容词，正文必须有对应表格或实验。

**四种通用命名式**（多篇验证）

| 命名式 | 结构 | 多篇实例 |
|--------|------|---------|
| 属性 + 基座 | `[Method]: [Falsifiable Property] + [Base Method]` | Mip-Splatting: Alias-free 3D Gaussian Splatting |
| 方法 + 能力 | `[Method] for [Target Capability]` | 3D Gaussian Splatting for Real-Time Radiance Field Rendering |
| 动词优先 | `[Verb]-ing [Task] ...` | Efficiently Reconstructing Dynamic Scenes One D4RT at a Time |
| 中文判断 + 锚点 | `[领域]新机遇/[判断]：[技术锚点]` | SLAM新机遇—高斯溅射技术 |

**类型变体**：方法论文用前三种；系统论文可在方法名后加 `A Unified Framework for ...`；基准论文用 `[Benchmark]: [What It Measures]`；综述用中文判断式或 `A Survey of ...`。

**模板（英文）**

```
[MethodName]: A [品类] for [任务] on/in [约束场景]
[MethodName]: [Falsifiable Property] [Base Method]
```

**反例**：题目只有方法名没有任务词；卖点词在正文找不到证据；中文题目口号化（"开启新纪元"）而不点技术对象。

**证据（多篇）**：3DGS、Mip-Splatting、D4RT、SeeLe、JIG 五种命名式覆盖方法、诊断、系统、综述等不同类型，说明"三要素 + 可证伪"是跨类型的共性。

### 2.3 摘要的撰写

**不变量：六段功能序列**

```
背景（1 句，领域地位/能力缺口） → 缺口（1-2 句，现有方法卡在哪）
→ 主张（1-2 句，我们提出什么） → 机制（1-2 句，为什么有效）
→ 证据（1-2 句，数字 + 口径） → 边界/意义（0-1 句，适用条件或下一步）
```

摘要不是目录，也不是引言缩略。每句一个功能，删掉任何一句后信息不减少的，就是废句。

**三种通用模板**（来自 10 篇 CVPR 2026 统计）

- **模板 A 机制叙事型**（3DGS、Mip-Splatting、D4RT、SeeLe）：背景→缺陷→提出→机制→数字。无贡献列表，全段机制叙事。
- **模板 B 缺陷倒逼型**（PhysGM）：零背景铺垫，"Despite advances..., current methods face key limitations:"，冒号后三条并列缺陷，再转折提方案。适合痛点极明确的论文。
- **模板 C 编号系统型**（NERFIFY）：问题一句 + 与通用方法划界一句 + (1)-(N) 编号创新 + 量化结果 + 开源。适合多模块系统论文。

**中文双模板**

- 中文综述（倒金字塔）：定义→价值→脉络→前置技术痛点→主角技术优势→组织方式（分类维度）→挑战与展望。
- 中文方法论文：针对问题→提出方法→核心机制→数据集与指标结果→消融结论→场景价值。

**类型变体**：范式型用 A 并突出"打破的旧假设"；诊断型用 A 但把"缺口"写成"根因"；系统型用 C；基准型用 B 并把"数据规模/效度"写进证据；综述型用中文倒金字塔。

**模板（英文，A 型）**

```
[领域地位 1 句]. However, [缺口 1 句]. In this paper, we propose [方法名], a [品类] designed to [目标] for [场景].
Specifically, [机制一] [做什么] by [为什么有效]. Meanwhile, [机制二] improves [环节] by [怎么做].
Both can be integrated into [现有管线] with [最小代价].
Collectively, our framework achieves [数字结果] while [质量/成本对比].
```

**数字口径**：写"up to X× speedup and Y% model reduction"这类带对比对象和单位的数字，不写"显著提升"。中文写"较____基线提升____"，不写"大幅提升"。

**关键词**：3 到 6 个，覆盖任务、方法、场景三层；中文核心另需中英文对照。

**证据（多篇）**：3DGS/Mip/D4RT 的摘要是 A 型；PhysGM 是 B 型；NERFIFY 是 C 型；SeeLe 是 A 型；JIG 是中文倒金字塔。五种形态共同说明"功能序列固定、句式可变"。

### 2.4 论文骨架

**不变量**

1. 方法与实验一一对应：方法有几个模块，实验就有几组对应消融。
2. 总览先行：方法节先给一张全页管线图，再进模块细节。
3. 配比约束：Method + Experiments 合计占正文 55% 到 70%；Introduction 6% 到 15%；Related Work 7% 到 15%。
4. 重型材料下沉：实现细节、数学推导、额外消融、局限讨论放附录，正文只留直觉与结论。

**五类骨架**

| 类型 | 骨架 | 重心 |
|------|------|------|
| 方法论文 | Intro → Related → Method（预备+总览+模块+训练）→ Exp（设置+主对比+消融+敏感性）→ Conclusion | 模块与消融一一对应 |
| 系统论文 | Intro → Related → System Overview → 模块 A/B/C → Deployment/Evaluation → Conclusion | 总览图 + 端到端证据 |
| 基准论文 | Intro → Related → Task Definition → Construction Pipeline → Evaluation Framework → Empirical Findings → Conclusion | 构建管线与效度 |
| 分析论文 | Intro → Related → Preliminaries → Formalization → 归因实验 → 理论-实验闭环 → Conclusion | 形式化与归因 |
| 中文综述 | 引言（定义→脉络→痛点→机会→目的）→ 领域概述 → 主角技术原理 → 按分类维度综述 → 问题与展望 → 结语 | 分类主轴贯穿全章 |

**跨类型结构装置**

- **方法小节与结果小节互链**：Mip-Splatting 的 Sec. 4 诊断对应 Sec. 5 两个 filter；SeeLe 的 3.3/3.4 对应 4.3 的 +HP/+CR。
- **诊断节前置**：诊断型论文把"为什么失败"放在方法之前（Mip-Splatting 的 Sensitivity to Sampling Rate）。
- **架构图先行**：系统型论文先给总览图，再逐模块展开（Proxy-GS、SeeLe、D4RT）。
- **分类轴贯穿**：综述型论文的每一节都回到同一分类维度，不中途换轴（JIG 的 RGB/RGB-D、多模态、语义）。

**模板（方法论文）**

```
1 Introduction
2 Related Work（按方法论组织，不按论文罗列）
3 Method
  3.1 Preliminaries / Problem Formulation
  3.2 Overview（全页管线图）
  3.3 [模块一]
  3.4 [模块二]
  3.5 Training / Integration
4 Experiments
  4.1 Setup（数据/基线/指标/硬件/超参）
  4.2 Main Results（质量 + 效率 + 任务指标）
  4.3 Ablation（逐模块，给 Δ）
  4.4 Sensitivity / Generalization / Stress Test
5 Conclusion
Appendix（实现细节、推导、额外消融、局限）
```

**反例**：方法有 3 个模块，实验只消融 1 个；Related Work 按作者罗列；综述中途换分类轴；正文塞满推导导致方法主线断裂。

### 2.5 引言的撰写

**不变量：五段功能序列**

```
P1 大图景（领域为什么重要，带来什么机会）
P2 缺口（现有路线卡在哪，必须可归因）
P3 洞察/根本问题（我们看到了什么，或一句反问把问题拔高）
P4 方案（我们提出什么，核心机制是什么）
P5 贡献（3-4 条，首条占品类位，末条是实验验证）
```

**五种通用引言弧线**（多篇验证，按论文类型选）

| 弧线 | 结构 | 适用 | 多篇实例 |
|------|------|------|---------|
| 权衡打破式 | 领域存在公认 trade-off → 我们同时拿到两端 | 范式/效率型 | 3DGS（quality + real-time）、D4RT（simplicity + power） |
| 诊断式 | 先展示失效症状 → 归因到机制 → 组件成为"显而易见的解" | 诊断改进型 | Mip-Splatting（erosion/dilation）、TemporalGS |
| 瓶颈分解式 | 把总瓶颈拆成 2-3 个可度量维度，逐条预告对策 | 系统/加速型 | SeeLe（计算强度/渲染低效/显存预算）、Proxy-GS |
| 编年史漏斗式 | 定义 → 分阶段历程 → 前置技术痛点 → 主角技术机会 → 本文目的 | 中文综述 | JIG（四阶段 SLAM 史） |
| 范式替换式 | 点名 incumbent 架构的结构性成本 → 用统一机制替换 | 范式创造型 | D4RT（多模块管线 → 统一 transformer） |

**承重句六类**

| 类型 | 识别信号 | 作用 |
|------|---------|------|
| 缺口句 | however / yet / remains / fails to | 建立张力 |
| 主张句 | we introduce / we propose | 给出方案 |
| first 声明 | the first / for the first time | 占品类位 |
| 机制句 | because / since / thereby | 解释为什么有效 |
| 量化句 | 数字 + 比较级 | 建立可信度 |
| 边界句 | limitation / only when | 划定适用范围 |

**模板（瓶颈分解式，通用）**

```
P1 ____ 已成为 ____ 的关键技术，带来 ____ 机会。
P2 然而 ____ 受限于 ____，具体而言 ____（数字对比）。
P3 瓶颈一：____。现有 ____ 做法 ____，但 ____。我们提出 ____，单此一项达到 ____。
P4 瓶颈二：____。观察表明 ____（比例/现象）。现有 ____ 仍 ____。我们提出 ____，额外达到 ____。
P5 瓶颈三：____。现有 ____ 忽略了 ____。我们设计 ____，实现 ____。
P6 综上，框架达到 ____，且与现有优化正交可叠加。贡献：（1）____；（2）____；（3）____。
```

**中文综述模板（编年史漏斗式）**

```
[概念]是指在____中同时实现____，在____领域有重要价值。
其发展经历多个阶段：1）____年代 ____；2）____年代 ____；3）____世纪 ____；4）近年 ____。
其中，[前置技术]因____而 ____，但 ____ 仍有较大提升空间。
为 ____，[主角技术]以 ____ 被引入，带来 ____。
本文对 ____ 进行系统梳理，旨在为 ____ 提供参考。
```

**证据（多篇）**：3DGS 的 trade-off 开场、Mip-Splatting 的诊断前置、SeeLe 的三瓶颈、D4RT 的 desired-properties、JIG 的四阶段编年史，覆盖五种弧线。共同点是"缺口可归因 + 方案可预告"。

**反例**：引言只讲背景不讲缺口；缺口写成"效果还不够好"（不可归因）；贡献 6 条以上（贪多）；首条贡献没有品类位。

### 2.6 核心创新点与方法的描述

**不变量：贡献四件套**

来自 10 篇 CVPR 2026 的统计（37 条创新点）：

```
1 条范式/品类声明（首条，占问题定义权）
+ 1-2 条技术创新（给机制）
+ 0-1 条数据/基准（筑护城河）
+ 1 条实验验证（末条，给证据）
```

数量收敛在 3 到 4 条，全部围绕单一主线。纯理论推导放附录，正文只讲直觉。

**三种方法叙事**

| 叙事 | 结构 | 适用 | 多篇实例 |
|------|------|------|---------|
| 诊断-对症 | 理论/观察 → 原方法错在哪 → 我们的修改 → 修好了什么（四拍） | 诊断改进型 | Mip-Splatting 两个 filter |
| 管线-模块 | 总览图 → 模块 A/B/C → 每个模块解决哪个断点 → 集成/训练 | 系统/加速型 | Proxy-GS、SeeLe、RoboTidy |
| 统一-替换 | 点名 incumbent 的多模块成本 → 一个统一机制 → 联合输出 | 范式创造型 | D4RT |

**方法节四件套**

```
Motivation：观察到的可量化现象（比例/曲线/诊断图）
Intuition：为什么这样设计有效（因果句 because/since/thereby）
Formulation：符号化（一符号一含义，符号表全文一致）
Algorithm：伪代码/步骤 + 关键超参取值依据（实验或上界）
```

**根因映射表**（诊断型必做）

| 症状 | 根因 | 组件 | 证据 |
|------|------|------|------|
| 伪影/模糊/慢/占显存 | 哪个机制导致 | 哪个模块对准它 | 哪张图/表 |

每个组件必须对准一个根因；每个根因必须能在图上观察到。做不到就说明组件是堆上去的。

**中文综述的方法描述**：三栏法，每行一个方法，列为"输入/策略方向/针对问题"，正文写"它用什么策略、解决什么问题、代价是什么"。

**图表角色**

- Fig.1 teaser：10 秒读出 headline，带对手弱点或数字。
- Fig.2 总览：方法导航，模块名 + 数据流。
- 诊断图：失败 vs 成功并排，标注根因。
- 玩具示例：最小配置讲清核心机制（3DGS 的 4 高斯、GradRig 的 3 splat、SeeLe 的 4 像素组）。
- 表格 caption：自带结论句，消融表直接给 Δ。

**模板（贡献声明）**

```
• 我们提出 [范式/品类]，这是首个 [working definition]。（首条占位）
• 我们设计 [技术一]，通过 [机制] 实现 [效果]。（技术）
• 我们构建 [数据/基准/系统]，覆盖 [规模/场景]。（数据，可选）
• 大量实验表明，[方法] 在 [数据集] 上达到 [指标]，优于 [基线]。（末条验证）
```

**证据（多篇）**：Mip-Splatting 的四拍诊断、SeeLe 的"观察 1.5% 高斯贡献 99% 像素"、Proxy-GS 的管线断点、D4RT 的统一替换、JIG 的三栏综述。形态不同，但都满足"每个组件对准一个根因/断点"。

### 2.7 实验的设计与分析

**不变量：四层证据 + 三线基线 + 指标三元组**

四层证据：

```
第一层 主对比：与赛道 SOTA 在同数据/同划分/同协议下比较
第二层 一致性与泛化：跨硬件、跨数据集、跨视角、跨场景
第三层 消融：逐模块 leave-one-out，给 Δ
第四层 敏感性/压力测试：超参网格、极端条件、负对照
```

三线基线：

```
① 直接基座/前身：证明相对最近亲属的增量（必要时对齐重训）
② 赛道 SOTA：证明相对最强对手的位置
③ 范式外基线：证明跨界对比下仍占优
```

指标三元组：

```
质量（PSNR/SSIM/LPIPS 或任务指标）
+ 效率（FPS/时间/显存/指令数，标注硬件与分辨率）
+ 任务特定/一致性（成功率、mIoU、FLIP、用户偏好率等）
```

**类型变体**

- 方法/系统型：四层证据齐全，另加"正交叠加"（把方法套到多个 SOTA 上，证明即插即用）。
- 诊断型：主对比之前先给"失效诊断"实验，证明根因真实存在。
- 基准型：证据重心是"基准效度"（难度自证、数据污染规避、与公认基准的落差）。
- 分析型：证据重心是"归因实验"与"理论-实验闭环"（预测中间量，不只对 headline）。
- 综述型：不跑新实验，用汇总表做横向比较，可信度来自分类完整性与比较公平性。

**三种结构性论证实验**（超出常规消融）

| 实验 | 作用 | 多篇实例 |
|------|------|---------|
| 正交叠加矩阵 | 把方法套到多个已有方法，证明通用性 | SeeLe 套 4 个基线；TemporalGS 套 6 种方法 |
| 控制变量归因 | 把性能变化拆到具体因素，隔离因果 | CoRef-GS 区分语义空间不兼容与坐标变换 |
| 理论-实验闭环 | 理论预测中间量，实验逐环节验证 | GS-VLA 的 ε→η→residual→Δ，全程报 R² |

**公平性红线**：所有对比方法必须同数据集、同版本、同分辨率、同划分、同评测协议。基线数字口径无法核验就重跑，不许静默换算或跨维度拼表。

**模板（实验矩阵）**

```
主对比：{基线集合} × {数据集集合} × {质量 + 效率 + 任务指标}
一致性与泛化：跨硬件 / 跨数据集 / 跨视角 / 负对照
消融：Base → +模块A → +模块B → Full（每步给 Δ）
敏感性：{超参1} × {超参2} 网格，画质量-性能权衡，定默认值
外溢：把方法套到 {其他 SOTA}，证明正交可叠加
```

**证据（多篇）**：3DGS 的 teaser 即结果表；Mip-Splatting 的 single-scale train / multi-scale test 协议；E-RayZer 的对齐重训；PhysGM 给对手喂初始化；SeeLe 的 4 基线 × 3 数据集；D4RT 的 throughput@FPS；JIG 的汇总表。共同点是"证据形态服务 claim，不服务堆量"。

### 2.8 结论的撰写

**不变量：三段收束**

```
回扣主线（我们解决了什么，一句话）
+ 边界（什么条件下不成立，或我们没覆盖什么）
+ 下一步（把工作定位成更大方向的一步）
```

结论不引入新概念、不复述实验数字清单、不写"综上所述"式空转。

**三种收束**

| 收束 | 结构 | 多篇实例 |
|------|------|---------|
| 范式挑战式 | 重申被挑战的旧假设，指出新范式的意义 | 3DGS（连续表示并非必需） |
| 第一步钩子式 | 自陈局限，把工作定位为理解根本限制的第一步 | SeeLe（GPU 支撑 3DGS 的根本限制） |
| 闭环式 | 脉络→痛点→机会→分类回顾→挑战与方向 | JIG 中文结语 |

**模板（方法论文）**

```
[领域]正在被 [技术] 改变。[技术] 作为 [定位] 提供 [价值]。
本文提出 [机制]，通过 [手段] 改善 [目标]。
我们认为，本工作是理解 [根本限制] 的第一步，可为 [下一代架构/方向] 提供参考。
```

**模板（中文综述）**

```
本文立足于 [领域]，首先梳理 [脉络]；针对 [前置技术痛点]，[主角技术] 以 [优势] 带来 [机会]。
本文从 [分类维度] 出发，分别介绍 [类一]、[类二]、[类三] 的方法，分析优势与不足；
最后总结当前 [挑战]，提出未来 [方向]，以期为 [读者群] 提供参考。
```

**反例**：结论复述实验数字；引入正文没出现的新概念；只写"未来我们将……"而不给边界。

## 3. 双轨差异：国际顶会与中文核心

同一论证链，两种表达习惯。差异是"体例层"，不是"逻辑层"。

| 环节 | 国际顶会（CVPR/SIGGRAPH/NeurIPS） | 中文核心（学报/中文期刊） |
|------|-----------------------------------|--------------------------|
| 摘要 | 单段，机制叙事，数字密集 | 中英双摘要，中文 300 字左右，英文对应；常用"定义→价值→脉络→痛点→优势→组织→挑战→展望" |
| 关键词 | 4-6 个英文 | 3-8 个中英文对照 |
| 引言 | 大图景→缺口→方案→贡献 bullet | 定义→发展历程→缺口→本文目的；常用"本文/我们"，少用 bullet |
| 方法 | 模块化，公式与伪代码并重 | 原理公式 + 分类叙述；综述按分类维度组织 |
| 实验 | 四层证据，表格密集 | 方法论文同样要主对比+消融；综述用汇总表横向比较 |
| 结论 | 短，留钩子 | "结语"闭环，常含"问题与展望"独立成节 |
| 参考文献 | 作者-年份或数字编号，arXiv 可用 | GB/T 7714，中文文献为主、英文文献为辅，需完整卷期页码 |
| 语言 | 简洁、主动语态、少形容词 | 平实、术语统一、少中英夹杂；首次出现缩略语给全称 |

**中文核心的额外硬性项**：中图法分类号、文献标识码、文章编号、收稿/修回日期、基金项目、作者简介、通信作者。不同期刊的具体字号与模板以其官方投稿指南为准（见各 `<venue>-format.md`）。

**双轨共同红线**：数字口径一致、术语全文统一、引用逐条核验、图表 self-contained。

## 4. 通用检查清单

```
□ 类型判定
  □ 已判定六类中的哪一类，主线只有一条
□ 论证链
  □ 问题、缺口、洞察、机制、证据、边界六环齐全
  □ 每个 claim 有证据节点
□ 题目
  □ 任务词 + 技术词 + 差异属性齐全
  □ 卖点词有正文证据
□ 摘要
  □ 六段功能序列齐全，无空转句
  □ 数字带口径，关键词 3-6
□ 骨架
  □ 方法小节与实验小节一一对应
  □ 总览图先行，配比在区间内
□ 引言
  □ 缺口可归因，有数字锚点
  □ 贡献 3-4 条，首条占品类位，末条验证
□ 方法
  □ 每个组件对准一个根因/断点
  □ 有玩具示例图，有超参取值依据
□ 实验
  □ 四层证据齐全，三线基线齐备
  □ 同数据/同划分/同协议，无跨维度拼表
  □ 至少一个结构性实验（正交/归因/理论闭环）
□ 结论
  □ 回扣主线 + 边界 + 下一步，不堆数字
□ 双轨
  □ 中文稿有中英摘要、关键词、分类号、GB/T 7714 参考文献
□ 诚信
  □ 引用逐条核验（3dgs-citation-audit.md）
  □ 不把"Highlight/高下载"写成"满分/高被引"
```

## 5. 从实例到规则的抽象方法

新增范文时，按下面四步把"单篇经验"转成"通用规则"，避免被单篇污染：

1. **抽功能，不抽措辞**：把每个段落标成"领域重要/现状/缺口/主张/机制/证据/边界"，只看功能序列。
2. **找共现**：同一功能序列至少在 2 篇不同类型论文中出现，才写入"不变量"。
3. **留变体**：只出现 1 次的写法，放"变体/证据"，不写成规则。
4. **可证伪**：每条规则必须能被"换一篇论文是否仍成立"检验；换一篇就不成立的，降格为实例。

本文件的规则栏，均满足"至少 2 篇、跨类型"；证据附录中的单篇细节，只用于说明规则如何落地。

## 6. 证据附录：两篇新增样本的拆解

> 说明：以下两篇是 2026-11-04 新增的样本，用于验证和补充上面的通用规则。它们是"实例"，不是"模板"。写作时不得把其模块名、数字、句式直接搬进自己的稿件。

### 6.1 样本 A：SeeLe（CVPR 2026 Highlight，方法论文 / 诊断改进 + 系统集成）

- 题目：SeeLe: A Unified Acceleration Framework for Real-Time Gaussian Splatting on Mobile Devices
- 标识：arXiv:2503.05168v3
- 类型判定：诊断改进 + 系统集成。主线是"移动端算力约束下的 3DGS 加速"。
- 论证链：问题（移动端 3DGS 达不到实时）→ 缺口（现有剪枝/量化以质量换速度，且保留统一渲染管线）→ 洞察（1.5% 高斯贡献 99% 像素；渲染某视点不需全部高斯）→ 机制（视点相关表示 + 贡献感知光栅化 + 主动显存管理）→ 证据（4 基线 × 3 数据集；消融 +HP/+CR；跨 GPU）→ 边界（依赖 GPU 特性，低功耗 GPU 收益更高）。
- 骨架：Intro → Related（高效表示/光栅化优化）→ Method（预备/总览/HP/CR/协同微调）→ Exp（设置/主对比/消融/敏感性）→ Conclusion。
- 可迁移点：三瓶颈分解式引言；"观察先行"的方法合法性；把方法套到多个 SOTA 的正交叠加；结论的"第一步"钩子。
- 不可迁移点：具体的 6.3×/39.1%、AGX Orin 数字、HP/CR 模块名。这些只属于该文。

### 6.2 样本 B：《SLAM新机遇—高斯溅射技术》（中国图象图形学报，综述）

- 题目：SLAM新机遇—高斯溅射技术
- 标识：中国图象图形学报，2025，30(6)：1792-1807，DOI:10.11834/jig.240443
- 类型判定：综述。主线是"GS 为 SLAM 带来的新机会"，分类轴是"应用输入类型"。
- 论证链：问题（SLAM 的实时建图需求）→ 缺口（NeRF 类 SLAM 渲染慢）→ 洞察（GS 的实时渲染 + 显式表示可同时提升速度与可编辑性）→ 机制（按 RGB/RGB-D、多模态、语义三类组织方法）→ 证据（Table 1 汇总 + 逐类优劣比较）→ 边界（实时性、基准一致化、大场景扩展性、灾难性遗忘）。
- 骨架：引言（定义→四阶段→NeRF 痛点→GS 机会→目的）→ 领域概述（原理/方法回顾）→ GS 原理（公式）→ 按三类综述 → 问题与展望 → 结语。
- 可迁移点：编年史漏斗式引言；分类轴贯穿全章；汇总表三栏（输入/策略/问题）；结语闭环。
- 不可迁移点：具体的四阶段史、三类划分、Table 1 内容。这些只属于该文。

### 6.3 两篇样本对通用规则的验证

| 通用规则 | SeeLe | JIG 综述 |
|---------|-------|---------|
| 论证链六环 | 齐全 | 齐全（证据环为汇总表） |
| 摘要六段 | 齐全 | 中文倒金字塔变体 |
| 方法↔实验对应 | 3.3/3.4 ↔ 4.3 | 3.1/3.2/3.3 ↔ Table 1 三组 |
| 每个组件对准一个根因 | HP↔无关高斯，CR↔贡献不均 | 三类↔三类应用缺口 |
| 边界声明 | 依赖 GPU 特性 | 四类挑战 |
| 双轨体例 | 英文单段摘要 | 中英双摘要 + 分类号 + GB/T 7714 |

结论：两篇样本验证了通用规则，但没有改变规则。规则来自多篇共性，样本只提供落地形态。

## 7. 维护与扩展

1. 新增范文时，先按 §5 四步抽象，再决定放"规则栏"还是"证据栏"。
2. 统计层更新以 `top-paper-patterns.md` 为准；逐句层更新以 `writing-patterns-from-top-papers.md` 为准；本文件只维护"跨类型不变量 + 变体矩阵"。
3. 任何单篇论文的数字、模块名、句式不得写入规则栏。
4. venue 体例以各 `<venue>-format.md` 的官方来源为准；本文件的 §3 只给通用差异，不替代期刊专项规范。
5. 事实核验：新增样本的 arXiv ID、DOI、venue 必须按 `3dgs-citation-audit.md` 三层校验；"满分/高被引"类口径必须以公开可核验信息为准，不得把 Highlight/高下载等同于满分/高被引。
